## 先决条件与发现

| 项目 | 归档/正式工程检查及处理 |
|---|---|
| SCCB | PB8=SDA，PB9=SCL；开漏、无内部上拉，沿用外部上拉条件。7位地址0x3C，线上读写地址0x79/0x78 |
| RESETB | PH15，先拉低，再启动XCLK，等待10ms后拉高，再等待20ms |
| XCLK | PA8/MCO1，经参考代码注明的R6连接摄像头；PLL1Q经MCO除10 |
| 原时钟错误 | 参考代码注释写PLL1Q=240MHz，但其HSI64MHz/M4*N60/Q2实际为480MHz，除10为48MHz；正式工程原来也相同 |
| 修正 | PLLQ改4：PLL1Q=240MHz，MCO除10得到24MHz；运行时检查PLL就绪、Q输出开启和Q频率 |
| 双核系统时钟 | PLLP不变，CM7=480MHz，CM4/AHB=240MHz，APB1=120MHz；以上为配置计算值，并非示波器实测 |
| 摄像头供电 | 旧main明确注明V0已拆R31、U10 CE硬件拉高。本次按该实板修订迁移，不擅自用GPIO驱动未知供电使能脚 |
| 供电未验证 | 归档未包含所链接的V0板卡交接文档/原理图，未见PWDN控制代码或供电测量。本轮无法确认实物是否已返修、电源轨是否建立、PWDN接法及上拉电平是否正确 |

上板前需核实实板确为上述V0供电修订、摄像头供电正常、SCCB外部上拉有效、RESETB和PA8/R6连接正常。供电和PWDN不可由当前软件自动测量或推断；s_camera_ready只代表板级初始化流程完成。

## 分层与文件

- CM7/BSP/bsp_camera.c/.h：摄像头引脚预配置、PLL1Q核对、MCO1输出、RESETB时序、DWT微秒延时、PB8/PB9软件SCCB。沿用寄存器地址写入后STOP、再START读单字节的旧V0方式；读取结束发送NACK。
- CM7/Device/Inc/ov5640_device.h、Device/Src/ov5640_device.c：Device导出对象，自动初始化，Ops.read_id读取0x300A/0x300B；通信成功但ID不等于0x5640时返回SYS_ERR_PROTOCOL。
- CM7/Application/app_ov5640.c/.h：1000ms周期Timer标记到期，App_Ov5640Run执行读取并保存10组结果；成功/失败均计次，10次后停止Timer，不进行第11次。
- CM7/Application/app_main.c/.h：通过现有Initcall注册App_Init，统一启动/轮询摄像头应用。
- CM7/Core/Src/main.c：USER CODE中加入App_Run及板级引脚预配置入口；PLLQ由2改4。其余双核启动、IPC/HSEM握手、MPU及系统时钟分频保留。
- h7_mac.ioc：同步DIVQ1=4及对应PLL1Q缓存频率，避免下次CubeMX还原Q2；未重新生成工程。PA8的MCO和摄像头GPIO由独立BSP负责，后续CubeMX分配引脚时应保留这些连接。
- MDK-ARM/h7_mac.uvprojx：新文件加入CM7对应Application/Device/BSP Group；已有Include Path可直接使用。CM4 Target继续排除CM7 Group。

新增注释使用简短中文//。CM4、Common、Scatter文件本次均未修改。

## 两核GPIOB并发处理

CM4 I2C2使用PB10/PB11，摄像头软件SCCB使用PB8/PB9，数据线不同。GPIO端口配置寄存器是两核共享资源，HAL_GPIO_Init对不同引脚也存在读改写交错风险。

因此在M7原HSEM释放CM4之前，BSP_Camera_EarlyInit预先使能GPIOA/B/H时钟，保持摄像头复位，并只配置摄像头引脚。后续BUS Init幂等跳过这些端口配置，不会与CM4 OLED初始化并发重配GPIOB。未改CM4代码，未调整IPC/HSEM握手先后顺序。

## 实板观察入口

正常启动约1秒后出现第1次结果，约10秒完成10次。Keil Watch观察：

```c
g_ov5640_probe.count
g_ov5640_probe.passed
g_ov5640_probe.failed
g_ov5640_probe.done
g_ov5640_probe.samples[0]  //至samples[9]
```

每项含chip_id和result。预期成功值为chip_id=0x5640、result=0。实际10次全成功时count=10、passed=10、failed=0、done=1。

- result=-9：SCCB某阶段NACK。
- result=-5：SDA或SCL空闲时仍被拉低。
- result=-10：两个寄存器读取成功，但组合ID不是0x5640。
- 初始化失败时可能count保持0；PLL1Q检查失败返回-4，DWT计数器未运行返回-7。

调试可进一步查看BSP私有s_sccb_error：0x01=SDA低，0x02=SCL低，0x04=写地址NACK，0x08=寄存器高字节NACK，0x10=寄存器低字节NACK，0x20=读地址NACK。SCCB未实现时钟延展或自动总线恢复，沿用旧最小探测能力。
