日期：2026-10-18

关键实际结果：

- 99ms 不发 Abort，100ms 发出一次 Abort。
- 完成结果只交付一次；普通错误交付 -9，HAL TIMEOUT 标志交付 -8。
- Abort 成功并收到完成回调后交付 -8；Abort 启动失败立即交付 -9 并保持 FAULT，后续同步/异步发送都拒绝。
- 不同事务地址逐次左移一位传入 HAL；0x55 当前事务的 Abort 地址为 0xAA。
- 129 字节完整接受并复制；130 字节、NULL、零长度及全部非法 uint8 地址均拒绝。
- PRIMASK=1 时完成 IRQ 不立即执行；恢复 0 后才通过 IRQ 入口交付回调。初始 PRIMASK 0、1 均准确恢复。
- 三个完成竞态位置均未错误进入 Abort，也未覆盖正常完成结果。
- Abort 返回 HAL_OK 但不回调时，模拟继续轮询 8 秒仍保持 ABORTING，只请求一次 Abort；这是已接受设计。
- Tick 从 0xFFFFFFF0 回绕后，99ms/100ms 边界判断正确。

## 正式工程检查

- `bsp_iic.h`、`sys_result.h`、真实 Framework 注册宏参与隔离编译；成功 0、失败负数符合当前接口。
- 三种 HAL 回调及两个 I2C2 IRQ 在 CM4 应用源码中各有一份定义，使用同一个私有 `hi2c2`。
- 正式 AXF 的向量 49/50 分别指向 I2C2 EV/ER 的强实现；`hi2c2` 仍为 LOCAL。
- NVIC 初始化启用 EV/ER，反初始化禁用并清 Pending；测试确认对称。
- EV/ER 均为 0/0，工程使用 PRIORITYGROUP_4；SysTick 为 15，未发现其他已启用外设 IRQ 的配置冲突。模拟不验证真实 IRQ 延迟或全局屏蔽期间 SysTick 的运行。
- BSP 初始化项位于 ER_FW_INIT，等级 BUS=1；不改变既有 GPIO、内核时钟选择及初始化流程。
- 正式 `bsp_iic.o` 的三个回调均为强定义。当前业务未引用 `BSP_IIC_WriteAsync()`、`BSP_IIC_TakeResult()`，正式链接器移除了这两个 API 及未使用的 Tx 完成路径；这不是回调重名或链接错误。

## 问题与建议（按影响排序）

1. **中等：异步硬件测试尚无调用入口。** 工程搜索及正式 AXF 均确认：当前业务仅 OLED 同步命令调用，无 WriteAsync/TakeResult 调用。若直接烧录现有固件，只能验证现有同步初始化路径，不能证明异步回调和超时路径已上板通过。最小建议：后续由独立硬件测试调用方发起异步事务，并在主循环定期调用 TakeResult，消费结果后再发下一笔。无需修改 BSP 核心算法；本次未添加该调用方。
2. **低：已接受的停滞策略。** Abort 回调永不出现则一直 ABORTING；Abort 启动失败则保持 FAULT。模拟已验证。硬件测试遇到这两种情况将无法继续发送，需结束本轮并重新启动测试。不建议在本次任务中增加自动恢复或二次超时。
3. **功能边界：OLED 刷新仍为未实现接口。** 当前 Oled_RefreshImpl 返回 NOT_SUPPORTED。可以验证 I2C2 与 SSD1306 初始化命令/应答，不能据此验收完整 Framebuffer 刷新。本次未改 OLED。

所测范围未发现需要修复的 BSP 状态机逻辑缺陷。上述接入建议影响异步硬件测试的可执行性，已接受停滞策略影响故障后的连续测试能力。

## 未验证内容

真实 PB10/PB11 电气波形与上拉、I2C2 实际 SCL 频率、SSD1306 电源/复位和 ACK、真实 HAL 内部寄存器路径、真实 IRQ 响应、STOP/Abort 是否产生及其回调时序、OLED 可见显示结果均未验证。

Mock 以可控返回值/状态模拟 HAL，并不执行真实 HAL 的寄存器级通信算法。T20 无回调场景符合约定，不能推导为真实故障的自动恢复能力。
