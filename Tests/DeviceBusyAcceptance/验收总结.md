# CM4 Device Model 定向验收

日期：2026-10-14。

## 结论

- 隔离仿真14/14通过，先前Init自重入问题已在当前实现中修复。
- Init/Start/Stop回调内部的全部3×3嵌套调用均返回SYS_ERR_BUSY（-5）；不重复执行回调，不覆盖外层BUSY状态。
- 本次只增加测试和报告，不修改生产Device/Framework源码或Keil配置。

## 核心验收项

| 项目 | 结果 |
|---|---|
| 正常转换 | UNINIT→BUSY→READY→BUSY→RUNNING→BUSY→READY；回调各1次 |
| Init回调重入自身及Start/Stop | 均返回-5；外层Init成功后READY |
| Start回调重入自身及Init/Stop | 均返回-5；外层Start成功后RUNNING |
| Stop回调重入自身及Init/Start | 均返回-5；外层Stop成功后READY |
| 已BUSY对象的生命周期调用 | Init/Start/Stop均返回-5，无回调，状态保持BUSY |
| NULL生命周期表/缺失Init | 返回-7，保持UNINIT |
| NULL生命周期表/缺失Start | 返回-7，保持READY |
| NULL生命周期表/缺失Stop | 返回-7，保持RUNNING |
| auto_init=false | 注册成功、Find返回原对象，不调用Init，保持UNINIT |
| auto_init=true | Device_InitAll调用Init一次并进入READY |
| DEVICE_EXPORT→Registry | 真正链接的静态导出表逐项注册成功，Find对象身份及链表双向关系正确 |
| Initcall集成 | BUS自动注册、DEVICE按策略初始化，成功后继续后续等级 |
| 回调失败 | Init/Start/Stop均原样返回IO=-9，并从BUSY退出到ERROR |

完整输入、预期、实际结果：busy_results.md、busy_results.json。
隔离测试直接包含当前实际CM4 Device/Initcall源码，使用模拟生命周期函数；每个用例创建全新仿真器。
测试Flash导出表由实际DEVICE_EXPORT宏生成；初始化数据恢复到ELF执行地址，不替换Device算法。

## ARMCC5 正式 Target

实际使用Keil UV4执行CM4全量重建，编译器为V5.06 update 7（build 960）。

```text
h7_mac_CM4.axf - 0 Error(s), 1 Warning(s).
UV4进程退出码：1（存在Warning）
```

全部Warning仅一条：

```text
../CM4/Device/Src/oled_device.c(63): warning: #111-D: statement is unreachable
    return SYS_OK;
```

原因：前一条语句已经返回SYS_ERR_NOT_SUPPORTED，后面的return SYS_OK不可达。
本次是验收，没有删除或修改该语句，也没有通过关闭Warning来隐藏问题。
完整构建日志：cm4_keil.log。隔离测试自身编译、链接无诊断。
