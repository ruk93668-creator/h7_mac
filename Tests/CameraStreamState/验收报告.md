# CameraStream五函数隔离状态机验收

## 结论

75/75 PASS，0 FAIL，0未执行；934605项断言。ARMCC5单元测试编译链接0 Error、0 Warning。正式源码与相关头文件SHA256均未变化。

测试对象为当前CM7/Media/Src/camera_capture.c中的五个内部函数：

- CameraStream_Init
- CameraStream_FindReplaceable
- CameraStream_OnFrameComplete
- CameraStream_GetFrame
- CameraStream_ReleaseFrame

## 方法

stream_test.c直接包含正式camera_capture.c，让静态函数在同一测试翻译单元可见，不复制或改写生产状态机。仅用测试头文件替代stm32h7xx.h中的PRIMASK接口，不链接HAL、CMSIS实现或真实BSP。

Unicorn执行ARMCC5编译的真实ARM机器码。映射独立128KB模拟SDRAM，模拟DMA向当前目标写入可区分的数据。replace_target桩记录M0/M1地址，在返回成功时才更新硬件地址模型；回调内检查软件尚未提前提交所有权。

普通完成中断在PRIMASK=1时排队，恢复为0后才执行。覆盖Get、Release临界区交错，以及初始PRIMASK=1时保持屏蔽。

## 核心验收

| 场景 | 输入 | 预期与实际 |
|---|---|---|
| 正常完成 | 分别从M0、M1完成 | 替换对应目标，原目标变READY，Get后IN_USE，Release后FREE；通过 |
| 旧READY覆盖 | 不取帧，连续30次完成 | 最新帧序号30，丢帧29，实际缓冲数据为最新帧；通过 |
| Application长时间持有 | 取第一帧后1000次完成 | 持有帧所有字节不变，DMA继续使用另两块，丢帧1000，释放后恢复交付；通过 |
| 地址切换失败 | FREE/READY候选下返回IO、BUSY、TIMEOUT | 原错误返回，整个软件对象及硬件地址模型不变，旧READY保持，成功重试后再提交；通过 |
| 临界区 | 屏蔽期间排队完成中断 | 不立即执行，不覆盖IN_USE，出口恢复原PRIMASK；通过 |
| 随机模型 | 每格式固定种子3000步 | 完成、获取、释放、切换失败与独立模型逐步一致；通过 |

25组用例分别使用Y8、RGB565、YUV422运行，共75项。独立模型累计9000步。每次有效状态转换检查：DMA索引不重叠、软件与硬件目标地址一致、两块DMA所有权、第三块FREE/READY/IN_USE与consumer_index一致、序号及丢帧计数一致。

还覆盖NULL参数、非法配置、DMA槽位越界、目标重叠、DMA状态错误、消费者越界/冲突、READY关联丢失、替换地址为空、容量不足、零长度、非Word长度、重复获取/释放及PRIMASK恢复。逐项输入、预期、实际及Pass/Fail见results.md、results.json。

## 执行

```powershell
python Tests/CameraStreamState/run_tests.py
```

编译器：ARM Compiler 5.06 update 7 (build 960)。ARMCC/armlink完整命令和版本输出保留在commands.json。测试执行环境为Unicorn，编译参数Cortex-M7、C99、O0；Python依赖复用Tests/OledAsyncAcceptance/python_deps。

## 限制

本次没有发现上述状态转换在已模拟前提下的逻辑失败，没有修改正式代码。

- replace_target失败测试假设回调返回失败时没有提交硬件地址。真实BSP若已部分切换后返回错误，必须由其契约及停止恢复流程处理，本套无法替它证明硬件回滚。
- 不验证DMA的真实CT位、双缓冲时序、实际IRQ优先级、缓存/MPU、OV5640信号和图像内容。
- OnFrameComplete按已完成帧的受保护上下文调用建模；这不证明连续采集已与真实BSP接通。
- SDRAM中的写入为隔离测试数据，不作为实板图像验收。
- 本轮只编译隔离测试程序，没有重新编译或烧录CM7/CM4正式Target。
