## 2. 调用链、职责及状态

详细时序、接口、状态及13份生产文件职责见 [设计说明](../../Docs/Design/C2.2B_双消费者接入.md)。

| 文件 | 本轮职责 |
| --- | --- |
| app_camera_consumer.c/.h | 每消费者的原Tx事务适配、身份、授权回复及可靠后继请求；不是第二张资格表 |
| app_camera.c/.h | 原唯一业务上下文；资格启用后拒绝旧资源控制消息，原停止推进不变 |
| camera_task.c | 首次准备工具；每轮一条资格消息准入、自唤醒、原CoreProcess及回复运输 |
| app_usb.c/.h、usb_task.c | USB异步启动命令与真实生命周期消息收发；原UVC/Bridge推进显式保留 |
| app_storage.c/.h、storage_task.c | 授权前保存用途且不挂载，授权后复用原业务；安全请求RELEASE但不伪造证明 |
| control_task.c | 取消Camera控制权，保留用户主输出请求、原ACK与超时接口 |
| h7_mac.uvprojx | 仅在CM7注册app_camera_consumer.c，CM4 Target元数据与基线相同 |

Camera仍拥有唯一Qualification表和资源状态。消费者对象的phase只是本方向事务进度，granted只是已接收的授权结果；均不能替代Media/FIFO引用计数。文件关闭、业务STOP ACK、资格释放、硬件停止分别表达。

停止后phase=RELEASE(4)、granted=1是本阶段生产预期边界。即使result为0，它也可能只是上一笔事务结果，不能视为当前RELEASE完成。客户端只在收到成功且带QUALIFICATION_RELEASED的固定回复后清grant并请求STOP_IF_IDLE。

### 保留的两项FAIL与生产准入约束

consumer_test.c用例17在O0/O2失败。它把两条冷SESSION_QUERY直接批量登记到原Core后才Process，原Qual_OtherWork让双方都终结BUSY。现场：session=0、starts=0、两客户端phase=FAILED(6)、result=0xFFFFFFFB、两资格INACTIVE、两回复均已成功运输。

本轮**未修改Core或Replay，也未加入终结BUSY自动重试**。CameraTask每轮只取一条消息，再执行原决策和回复Flush，随后用原WAKE提示继续处理队列，避免先把两条冷QUERY同时登记为Core候选。新CameraTask用例5在O0/O2通过：两条请求同时位于真实Task接收夹具的队列，两路最终GRANTED，资源只启动一次，自唤醒4次且有界。

这验证的是生产适配约束，不是修复Core批量行为。原批量用例17不删除、不降断言；后续不得绕过该准入规则。若要求Core本身接受批量冷QUERY并自动完成，需要单独审核。任务优先级不作为正确性证明。

独立停止后仍需NULL证明的生产用例保留等待。完成释放和长期启停用例使用明确资源证明桩；它们不能替代C2.2C或硬件验收。

## 6. 生产范围与未解决风险

scope_results.json记录13份生产/工程差异及完整源码哈希，证明构建快照等于工作树。CM4、Device、Media/FIFO、Bridge/Dispatcher、USB Core/UVC、StorageFS/DiskIO/SD_Block/BSP和原Tx/Rx/Replay逐字未改。Storage OfferFrame、ProcessReturns、Snapshot、CloseAvi、Release、Write函数体逐字不变；不新增强制释放能力。

P1：Core批量冷QUERY限制仍在，生产必须经过CameraTask串行准入。新负例保留FAIL，需审核该约束。

P1：生产真实released/idle证明尚未提供，RELEASE保持等待；最后消费者退出不能宣称Camera停机，同一路再次START可能BUSY。C2.2C仍需完整真实Lease证明、Shutdown和停止/重启闭环。

P1：旧同步/轨迹夹具尚未适配生命周期预条件，兼容性门禁未全过，不建议合并main。

P2：USB/Storage反方向Shutdown请求未接入；不会伪造ACK。协议异常和超时保留原事务，没有清空或自动恢复策略。

P2：Control原5000ms超时现在覆盖USB请求中的Camera准备时间，硬件慢启动/迟到回复需要实板观察；本轮不擅自放宽超时。

P2：新路径实际FPS、USB/SD并行吞吐、通知时序、IPC延迟和任务实际栈尚未测量。配置FPS、软件桩、静态Map和先前版本实板反馈不能冒充本版本实测。
