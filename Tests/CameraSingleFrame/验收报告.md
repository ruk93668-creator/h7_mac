# CM7 Application 单帧采集联调验收

本轮完成固件接入、两核编译和模拟验收。没有操作实板，不代表真实DVP采样或图像内容通过。

|---|---|

## 调用链

```text
Framework_InitRuntime → 原App_Init → App_CameraInit
    → Device配置160×120 Y8内部彩条，成功后才继续
    → CameraCapture_Init(同一配置)
    → CameraCapture_Start（只提交一次）

main原有Main_Run
    → Framework_Run
    → App_Run → App_CameraRun
        → CameraCapture_Process
        → GetLastResult：失败则同时记录GetLastStopResult，结束联调
        → GetFrame：无帧则返回下一轮
        → check模块统计完整图像
        → ReleaseFrame
        → 固定验收结果，不再自动启动
```

采集由中断和Media轮询推进，Application没有等待硬件完成的循环。统计是主循环中的一次有限CPU计算，没有ISR统计、打印、USB、连续采集或图像算法。

## Keil Watch

在Watch中添加 `g_camera_check` 展开。正式CM7 Map确认该变量已链接（本次地址0x20000070，后续构建可能变化，应使用符号名）。

| 变量 | 正常单帧预期 |
|---|---|
| finished / success | 1 / 1；只有处理完成并释放成功才置success |
| sensor_result / media_result / start_result | 均为SYS_OK（0） |
| capture_result / frame_result / release_result | 均为SYS_OK（0） |
| attempted_steps | 正常为0x3F，表示已执行Sensor、Media、Start、Capture、Frame、Release；未执行Stop |
| frame_count | 1，不随主循环继续增加 |
| frame_address | 0xD0000400 |
| width / height / format | 160 / 120 / CAMERA_PIXEL_FORMAT_Y8（0） |
| size_bytes / sampled_bytes | 19200 / 19200 |
| stats_valid | 1；表示统计已完成，不等同最终验收成功 |
| pixel_min / pixel_max | 0～255范围内，内部彩条应有亮度差：min < max |
| pixel_sum | 逐字节求和；19200字节范围为0～4896000 |
| crc32 | CRC-32/ISO-HDLC（IEEE），反射多项式0xEDB88320，初值/最终异或均为0xFFFFFFFF |

`attempted_steps`位定义：bit0 Sensor、bit1 Media、bit2 Start、bit3 Capture、bit4 Frame统计、bit5 Release、bit6 Stop。未执行步骤的结果默认0，必须结合该位判断，不能将默认0误认为步骤已成功。

`init_error == 0`仅表示初始化及提交采集成功，不代表图像采集完成。采集结果看finished/success以及分阶段结果。

图像范围为0xD0000400～0xD0004EFF，共19200字节。Release不清零图像，本轮不启动下一帧，便于Memory窗口查看。未修改MPU或Cache配置。

## 错误判定

| 情况 | 预期Watch |
|---|---|
| 传感器配置失败 | sensor_result为原错误，Media/Start不执行，finished=1、success=0 |
| Media初始化失败 | media_result为错误，Start不执行 |
| 启动失败 | start_result为原错误；单独执行Stop并记录stop_result，不交付帧 |
| 采集IO错误 | capture_result=-9，stop_result反映实际恢复结果，success=0 |
| 采集超时 | capture_result=-8；沿用Media的100ms超时，单独保存Stop结果 |
| Stop恢复失败 | stop_result为负数；保留先前capture_result/start_result，禁止自动重启，不计算图像统计 |
| 完成和错误同到 | 错误优先，不交付完整帧 |
| 帧描述错误 | frame_result为参数或协议错误；不读取非法长度数据，仍尝试释放 |
| 全零/全FF等单色帧 | 保留统计，frame_result=-10，success=0；只拒绝无亮度差，不做完整彩条识别 |
| 释放失败 | release_result为负数，success=0；不能因统计成功而报告整体验收成功 |

正常完成并不额外Stop；错误时Media内部Stop的结果由新getter交给Application。某次Stop失败后，即使之后手动恢复成功，已固定的本轮失败报告也不改成成功。

启动失败时，原Framework Initcall仍会返回负数并走现有初始化失败策略；可在Watch查看报告。成功完成或采集失败后，Application均停止本轮轮询，不反复重试、不覆盖现场。

## 实板验收与后续清理

上板后运行两核，等待g_camera_check.finished变1，再检查success及各步骤结果，查看19200字节图像及统计。实际彩条的精确min/max/sum/CRC没有在本轮测量，不预设固定值；可从Keil导出恰好19200字节，用Python的zlib.crc32独立核对。100ms超时沿用现有Media设置，本轮未实测帧周期。

本轮不下载或操作实板，真实像素、DVP电气/同步、DMA总线负载及采集耗时均未验证。不能把模拟图像或g_camera_check.success在模拟器中为1当作实板通过。

实板通过后，临时统计和Watch均集中在app_camera_check.c/.h；可移除这对文件、Keil登记及app_camera.c中的Check调用。Media的停止结果查询属于正常错误报告能力，可保留。独立测试和报告留在Tests，不加入HAL或BSP业务路径。
