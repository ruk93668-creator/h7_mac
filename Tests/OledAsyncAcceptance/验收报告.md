## 核心验收

| 要求 | 实际结果 |
|---|---|
| 正常刷新 | CMD0→DATA0→CMD1→DATA1→CMD2→DATA2→CMD3→DATA3；共8笔事务 |
| 传输未完成 | WAIT_CMD、WAIT_DATA分别连续12次Process，返回0，页号/状态/事务数量保持不变 |
| 重复Refresh | 两种等待状态均返回BUSY=-5，不再次提交BSP |
| 通信错误 | 8个CMD/DATA阶段逐一注入IO/TIMEOUT完成错误；逐一注入BUSY/IO/TIMEOUT提交失败；均原样返回错误并回IDLE |
| 最后一页 | DATA3完成后回IDLE，page保持3；后续10次Process不取结果、不产生CMD4 |
| 连续两帧 | 更换全部帧数据后第二帧从CMD0启动，累计16笔事务，全部数据正确 |

每页命令严格核对：4字节 `00 B0|page 00 10`。每页数据严格核对：129字节 `40` 加对应128字节帧缓冲。检查了7位地址0x3C、状态转换、页号及发送顺序。

补充：NULL输入、非法刷新状态、通信完成错误后重新发起整帧均通过。完成错误后的重启针对BSP已交付并消费结果的情形，不意味着BSP FAULT状态可以自动恢复。

## 代码位置及问题

本次50例无失败项，因此没有需要自动修复的问题。关键检查位置：

- CM4/Device/Src/oled_device.c:252，Oled_RefreshImpl：重复启动保护、CMD0提交后进入WAIT_CMD。
- 同文件:314、355：结果未就绪时返回，保持刷新状态。
- 同文件:320、342、361、385：通信完成错误或提交错误后回IDLE并原样返回错误。
