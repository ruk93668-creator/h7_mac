## 类型与配置传递

```c
typedef enum
{
    CAMERA_PIXEL_FORMAT_Y8 = 0U
} CameraPixelFormat_t;

typedef struct
{
    uint16_t width;
    uint16_t height;
    CameraPixelFormat_t format;
} CameraConfig_t;
```

当前传递位置：

```text
Application的static const s_camera_config
    ↓ App_CameraGetConfig()
App_CameraInit()
    ↓ camera->ops->configure(camera, config)
OV5640 Device校验配置
    ↓ 对应唯一已验证预设
原组件初始化 + PCLK/行帧周期 + 彩条 + 输出开启
```

Device不维护另一份“当前配置”，不修改传入对象。Device中的160/120检查是能力限制，不是另一份可独立修改的应用配置；只修改Application分辨率不能启用未验收模式。ST组件内原有其他格式/尺寸能力未开放到正式Device。

未来Media接入约定（本次未实现）：Application取得同一只读配置指针，在Device配置成功后将其传给未来的Media初始化接口；Media只依赖公共camera_config.h，不反向包含Application头文件，不另设分辨率和格式宏。配置为静态const对象，生命周期覆盖固件运行期，Media可保存该指针并按格式计算帧大小。当前Y8帧大小为19200字节。本次没有新增Media接口、状态机或Framebuffer。

## 支持范围

| 输入 | 返回 | 传感器寄存器访问 |
|---|---|---|
| camera或config为NULL，宽或高为0 | SYS_ERR_INVALID_ARG | 无 |
| 非160×120的非零尺寸、未知或非法格式值 | SYS_ERR_NOT_SUPPORTED | 无 |
| 160×120 Y8 | 执行原有ID检查及初始化 | 与原流程一致 |

read_id接口不变。旧configure_y8_colorbar(camera)已迁移为configure(camera, config)，正式调用方全部更新；后续外部调用需使用新签名。保留彩条开启行为，没有增加通用彩条开关。

## 寄存器兼容性

修改前先执行42项现有测试，逐位模拟SCCB，从真实BSP产生的总线字节解码每次被接受的写入，记录完整“寄存器地址+值”序列和最终64KB寄存器模型。修改后对相同42个输入比较：

- 写入数量：42/42一致。
- 完整写入序列SHA256：42/42一致。
- 最终寄存器模型SHA256：42/42一致。
- 已记录的SCCB总线前缀：42/42一致。
- 正常每次配置仍为272笔寄存器写入；原17项回读仍只在隔离测试执行。

详见register_comparison.json、baseline_camera_results.json、Camera/results.json。复位、PCLK、行帧周期、160×120 Y8和彩条相关操作未改变。
