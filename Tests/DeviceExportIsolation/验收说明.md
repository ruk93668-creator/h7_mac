# CM4 Device Export 检查

日期：2026-10-14。仅对 CM4 做实验。

## 配置检查

- DeviceExport_t、DEVICE_EXPORT 宏已存在；导出项为 const DeviceExport_t，4字节对齐，写入 .device_export。
- oled_device.c 已在 BOARD_HAS_OLED 条件下使用 DEVICE_EXPORT(s_oled)；当前 BOARD_HAS_OLED=1。
- CM4生产Scatter已有 ER_DEVICE_EXPORT +0，收集 *(.device_export)。
- 本次只补充 CM4 Linker Misc 的 --keep=*(.device_export)。CM7源码、Target和Scatter未改。
- 宏中的 DeviceExport_t 定义虽位于宏定义之后，但在 oled_device.c 展开宏前已定义，不构成类型顺序错误。

## 正式 Target：未通过

实际 Keil CM4 构建为5 Error、4 Warning，未生成可验收的新AXF。

缺失定义：

```text
Device_RegisterAll
Device_InitAll
Oled_ClearImpl
Oled_DrawPixelImpl
Oled_RefreshImpl
```

OLED另有不可达 return SYS_OK 警告。本次未补写设备功能或修改这些函数。
实际日志：cm4_keil.log。

实际编译生成的 oled_device.o 已包含 .device_export，大小4字节；其指针重定位目标为 s_oled（具体符号记录见检查输出）。
这能确认编译器产生了导出项，但不能代替正式镜像完成链接后的验证。

## 隔离链接实验：通过

export_probe.c 直接包含当前实际 CM4 oled_device.c，并仅在测试翻译单元中补充3个缺失OLED行为函数的 NOT_SUPPORTED 桩。
使用实际 CM4生产Scatter和相同保留选项链接独立AXF；没有加入Keil Target，没有烧录。

| 检查项 | 实际结果 |
|---|---|
| 输入段 | .device_export |
| 输出执行区 | ER_DEVICE_EXPORT |
| 导出项大小 | 4字节 |
| 导出项执行地址 | 0x0810008C，属于CM4 Flash |
| 导出项加载地址 | 0x0810008C，与执行地址相同 |
| 表内原始字节 | 00 00 00 10（小端） |
| 解析后的指针 | 0x10000000 |
| s_oled 地址 | 0x10000000 |
| &s_oled.base | base是实际结构首成员，因此等于s_oled地址；与表内指针相符 |

证据：export_probe.map、probe_result.json、inspect_export.py。
隔离编译继承原OLED的1条不可达语句警告；探针链接另有2条无关选择器/测试保留项警告，未将其宣称为无警告构建。

## 结论

导出宏、Scatter选择器及保留配置在隔离镜像中能正确形成Flash指针表。
当前正式CM4 Target仍被未实现函数阻塞，正式镜像的最终地址和内容暂未验证；不能将探针地址当作正式工程最终地址。
