# SDMMC IDMA与FatFS：分层实板验收回顾

记录日期：2026-11-10。回顾08B、08C；旧入口、地址和指令仅用于理解历史过程，不是当前正常固件的操作说明。

**状态：用户反馈08B真实扇区读写、恢复和五分钟只读压力，以及08C挂载/卸载、131109B文件往返均符合预期。掉电安全、长期文件系统稳定性和MSC切换没有因此完成验收。**

本篇只记录从块设备到文件系统的验证链路，不混入录像帧率、检测焊接、USB降帧或DCMI错误的具体排查。

## 为什么没有识卡成功就直接接JPEG保存

当时已经读到卡容量和512B逻辑块大小，但这只能证明识卡命令路径成立，不证明IDMA、Cache一致性和文件系统可用。

如果一次接入相机、JPEG、FatFS和SD写入，失败时难以分层。因此我先验证原始块读写，再验证文件系统，最后才接保存业务。

~~~text
识卡成功
    ≠ IDMA数据阶段完成
    ≠ 卡内部写入结束并恢复TRANSFER
    ≠ 文件已经同步、关闭且能重开读取
~~~

HAL返回、完成回调、卡状态和文件结果是不同证据，不能因为其中一个成功就替后面所有阶段背书。

## 1. 先固定内存边界，完成IDMA只读

当时选择：

- 400kHz、1-bit识卡，成功后切换4-bit、40MHz。
- 不重配PLL1/PLL2，保留相机、SDRAM时钟。
- 32KiB、32B对齐的独立AXI缓冲，历史起点0x24000000。
- 联合核对Scatter、MPU、Cache和地址范围，不把任务栈或DTCM地址直接交给SDMMC IDMA。
- BSP负责物理传输，SD_Block负责任务等待和访问所有权。

我也曾疑惑“其他DMA能用，为什么SDMMC不能直接用”。这里必须按具体总线主设备核对可达性。CPU可访问、其他DMA可访问、Cache关闭，都不能代替SDMMC IDMA的地址验证；Camera原图在SDRAM，也不是DMA1访问DTCM的证据。

| 动作 | 要验证什么 | 实板反馈 |
| --- | --- | --- |
| 手动只读触发 | 不在初始化中自动改卡 | 用户确认只读测试通过 |
| 查询真实卡信息 | 后续身份和边界检查有依据 | 容量7795113984B，块大小512B |
| IDMA重复读取校验 | 确认实际数据往返一致 | read_crc=repeat_crc=0xA55822CC |
| 核对工作模式 | 不把配置值等同于已走到该模式 | 用户确认4-bit、40MHz IDMA只读验收符合预期 |

只读通过不等于写入授权，也不代表原数据恢复已经验证。

## 2. 先明确授权LBA，再做写入与恢复

用户明确允许写卡后，我仍先获取CID和MBR，避免猜测可覆盖区域。

~~~text
CID：9F544930 / 30303030 / 00000189 / BD013CBA
整卡容量：7795113984B
当时分区1：LBA1024～17407
当时分区2：LBA17408～140287
历史测试区：LBA1048576～1048583，8扇区、4096B
~~~

测试区当时在已声明分区之外，没有覆盖LBA0。**后来分区布局已经改变，历史授权区不能再当作当前空闲区使用。**

真实流程：

~~~text
校验身份和范围 → 备份原扇区 → 写测试数据
→ 回读比较 → 恢复原扇区 → 再回读确认恢复
~~~

用户反馈：

~~~text
state=2
result=0
restore_result=0
restore_required=0
~~~

只看到result=0不够；恢复结果和待恢复标志也符合预期，才能支持原扇区已恢复。发生恢复失败时不能直接复位或断电后假定数据还在。

## 3. 五分钟只读压力验证什么

它验证重复读取、数据校验、任务等待及并行业务，而不是再次证明能识卡，也不是最大带宽测试。

| 项目 | 用户提供的实板结果 |
| --- | --- |
| elapsed_ms | 300064ms |
| attempted_rounds / completed_rounds | 846 / 846 |
| bytes_read | 28154880B |
| I/O、CRC、缓冲错误 | 均0 |
| reference_crc / last_crc | 一致 |
| result | 0 |
| 视频、OLED | 正常显示 |

截图记录average_read_us=4223、max_read_ms=54。bytes_per_second=93829包含轮间等待和其他任务时间，不是SD卡最大连续读取速度；40MHz、4-bit也不是实测文件写入带宽。

这轮是只读压力，不能改写成五分钟持续写入验收。期间出现过USB性能现象，但属于独立问题，这里不展开，也不把无I/O错误说成所有性能均不受影响。

## 4. FatFS验收先遇到固件和符号问题

08C使用独立验收入口，正常Initcall不自动识卡、挂载或写文件。

最初g_fatfs_acceptance字段出现类似地址或指令的数据，后面还有0xA5A5A5A5。当时不能仅凭A5认定栈溢出；我先核对正在运行的固件和调试符号。

| 顺序 | 观察与动作 | 当时的判断 |
| --- | --- | --- |
| 1 | ready、request、state不符合初始状态，部分字段是A5 | 可能是错地址、初始化或镜像不一致，先不认定越栈 |
| 2 | 读历史校验地址0x080008C0，得到0xF0154617 | 与当轮验收AXF预期0x2014E002不符，需要对齐镜像 |
| 3 | 明确下载并运行对应验收AXF | 不能把加载符号当成已经证明板上固件一致 |
| 4 | 再读Flash和入口状态 | 用户确认校验值符合预期，ready=1、初始state=0 |

该Flash地址和预期字只适用于历史镜像，不是通用固件标识，也不能套用到当前录像工程。

## 5. 先只读挂载，再授权文件写入

先执行真实识卡、只读挂载和卸载，用户确认state=2、result=0、cleanup_result=0。

当时卷信息：

~~~text
MBR分区号：1
first_lba：1024（0x400）
sector_count：16384（0x4000）
卷大小：8MiB
FatFS实际识别：FAT12
~~~

这一步让我明确区分：卡容量约7.8GB，不代表挂载卷也有这么大；MBR分区类型标签也不是实际文件系统类型的最终证明。

之后才把真实CID、容量和卷范围填入验收授权字段，显式确认允许创建测试文件。没有自动格式化、创建分区或覆盖旧文件。

## 6. 131109B文件往返为什么比512B更有用

131109B＝128KiB+37B，大于32KiB中转容量，且不是512B整数倍。它覆盖多次传输和文件尾部处理，而不是只做一次整扇区拷贝。

~~~text
CREATE_NEW新建未占用的8.3文件名
→ 写131109B → f_sync → 关闭
→ 重开 → 回读 → 逐字节、CRC和边界校验
→ 关闭、卸载
~~~

用户确认：

~~~text
state=2
result=cleanup_result=0
bytes_written=bytes_read=131109
write_crc=read_crc=0x42A20526
buffer_valid=1
~~~

这支持本次文件写入、同步、关闭和重开读取成功；不代表突然断电时也能保证文件、目录和FAT完整。

原始08C软件验收为FatFS108/108、SD块设备556/556，两核完整编译0 Error、0 Warning。软件结果与用户操作的真实硬件结果分开记录，不拿后来增加的测试数量倒填当时记录。

## 7. 验收结束要恢复什么

- 恢复正常Keil输出目录与Target配置，核对真正下载的AXF。
- 正常启动不混入SdTest、压力任务、测试宏和专用验收缓冲。
- 独立测试源码和构建脚本保留在测试范围，不默认执行真实写卡。
- 旧Map地址和Watch表不能跨版本照搬。
- 不自动删除卡内测试文件，不把历史LBA授权永久复用。

当前合并与本地清理已暂停，本次只是文档回顾，不执行实卡读写或修改生产代码。

## 结论与未验证边界

用户反馈已通过：

1. 4-bit、40MHz IDMA只读与重复校验。
2. 历史授权区域的真实写入、回读及原数据恢复。
3. 846轮、五分钟只读压力，无I/O、CRC和边界错误。
4. FatFS挂载、卸载和131109B文件往返。

不能因此宣称：

- 卡已达到最大持续读写速度。
- 实卡写满、掉卡、突然断电及所有恢复组合已验证。
- 长期连续文件写入稳定性已经证明。
- JPEG保存、录像或MSC在08C就已经完成。
- 历史原始扇区测试区在当前分区布局下仍可覆盖。

## 面试60～90秒复述

> 我没有识卡成功后就直接接相机保存，而是分层验证。先固定AXI中转和Cache边界，用低速1-bit识卡，再切到4-bit、40MHz，通过真实IDMA读取和重复CRC。写入前按真实CID、容量和MBR确认授权区，先备份，再写入、回读、恢复，最后核对恢复结果。五分钟压力完成846轮，没有I/O、CRC或边界错误，但我没有把带轮间等待的吞吐当成最大带宽。接入FatFS后，Watch一度像是在读地址和A5填充值，我先核对板上Flash与验收镜像，没有直接认定栈溢出。最后新建131109B文件，完成同步、关闭、重开和逐字节、CRC校验。这样我区分了识卡、数据完成、卡就绪和文件结果各层证据，同时保留掉电安全、长期稳定性等未验证边界。
