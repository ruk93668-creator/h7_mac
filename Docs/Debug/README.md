## 讲述一个案例的顺序

1. 现象与影响：在哪里失败，哪些功能仍正常？
2. 最初假设：为什么当时先查它，而不是事后说“我马上知道”？
3. 一项具体动作：断点、寄存器、抓包或单因素对照。
4. 证据与转向：哪一个值/反例推翻了什么？
5. 最小改动：为什么没有同时改多个层或放宽安全检查？
6. 验证和边界：证明到哪一步，哪些还没完成？

可用的转折句：“当时我还不知道原因，所以先……”“这条证据只能说明……”“后来的对照推翻了我原来的判断……”“我把两个独立故障拆开，没有用一个原因解释全部现象……”

## 特别容易讲过头的地方

- 枚举成功≠协商成功≠Alt1成功≠有Payload≠完整帧≠长期稳定。
- Submit成功是借用被接受，不是PC已收到图像；不能提前释放IN_USE帧。
- URB成功不等于有图像字节；SELECT_INTERFACE主机失败也不一定是设备STALL。
- 软件配置25 FPS、ffplay格式信息、软件模拟PASS，都不是实测成功FPS。
- 中断栈下面的前台函数不一定是故障原因；错误清理后的0不推翻首次错误现场。
- Debug暂停和读取有副作用寄存器会改变被观察对象。
- 若没做恢复对照和长时间测试，就把结论限定在当前证据，不补造闭环。
