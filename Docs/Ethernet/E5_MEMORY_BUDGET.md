# E5 内存预算与链接布局

## CM7 实际链接结果

Keil `eth_e5.map` 中，Region 5 的执行基址为 `0x24010000`，容量 65,536 B，实际使用 50,776 B，余量 **14,760 B**。相对 E4.2 的 20,900 B 增加 29,876 B，达到 8 KiB 余量目标。

| 固件 | Code | RO | RW | ZI | 链接 ROM（Code + RO + RW） | 链接 RAM（RW + ZI） |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| E4.2 对照 | 38,022 | 1,242 | 212 | 38,720 | 39,476 | 38,932 |
| E5 | 67,230 | 1,614 | 348 | 68,588 | 69,192 | 68,936 |
| 增量 | 29,208 | 372 | 136 | 29,868 | 29,716 | 30,004 |

| 对象 | 容量／槽位 | 链接地址 | 链接 B |
| --- | --- | --- | ---: |
| lwIP heap | `MEM_SIZE=12288` | `0x24015D08` | 12,307 |
| TCP PCB | 6 | `0x24018DE8` | 915 |
| TCP Listen PCB | 1 | `0x24019186` | 31 |
| TCP Segment | 24 | `0x240191B0` | 387 |
| UDP PCB | 2 | `0x24018D9A` | 67 |
| RAW PCB | 4 | `0x24018D1C` | 115 |
| SYS_TIMEOUT | 7 | `0x2401933E` | 115 |
| PBUF 元数据池 | 16 | `0x240193BC` | 259 |
| PBUF_POOL | 24 × 512 B 数据区 | `0x240194CA` | 12,675 |
| TCP 角色上下文和字节环 | 2 ×（2 × 2920 B + 状态） | `0x24010668` | 11,896 |
| E5 测试协议通道 | 流式解析、待发送帧及序号窗口 | `0x240135D8` | 4,680 |
| Ethernet DMA | 描述符与内部缓冲 | `0x24078000` | 12,544 |

池数字取自 ARMCC 链接符号，含 lwIP 元素元数据和内存对齐空间。6 个 TCP PCB 给两个活动角色和最多四个额外暂态 PCB 留空间，监听 PCB 来自独立池。一个 UDP PCB 用于 DHCP，另一个用于 E5。MSS 为 1460 B，每角色 TCP 通告接收窗口及 lwIP 发送缓冲各为 2920 B，每 PCB 的 `TCP_SND_QUEUELEN` 为 8。关闭乱序缓存后，超前数据需等待 TCP 重传。

Region 4 用既有 MPU 配置映射非缓存 AXI SRAM。Region 5 容纳 CPU 管理的 lwIP、TCP 字节环和测试缓冲。固件在配置 MPU 后启用 DCache，收发沿用既有 netif 与驱动的复制边界，DMA 始终持有自己的非缓存缓冲。实际板上 DCache/MPU 状态和运行期间池峰值为 **NOT_RUN**，验收时通过 `g_e5_status` 记录。故障注入的主机峰值见实施报告。
