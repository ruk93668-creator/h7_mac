# U7 编码器临时实板入口

本次按用户补充要求把 U7 接到 UI2 现有事件入口。正式 CM4 Target 默认关闭 `OLED_UI2_TEST_INPUT` 及 `OLED_UI2_U7_INPUT`。启用两项的实验工程位于 `D:\32\STM32H7\h7_mac_ui\UI2-U7\MDK-ARM\h7_mac.uvprojx`。

| 信号 | 2026-11-16 原理图 |
|---|---|
| A | PI6 |
| B | PC15，复用 LSE OSC32_OUT |
| S / PUSH | PI9，低有效 |
| C / COM | GND |

引脚依据用户提供的原理图主控页和调试扩展页。参考工程的 [Driver/key.c](https://github.com/ruk93668-creator/py_rtos_pro/blob/HEAD/Driver/key.c) 使用两相跳变积累与事件消费。本实现使用相同的接口分离思路，在原 Application 主循环按毫秒读取 GPIO，未复用参考工程的 EXTI 引脚或回调。器件的双相与按压 COM 接点见 [SIQ 系列资料](https://atta.szlcsc.com/upload/public/pdf/source/20220728/2FBC1A98A06DC86460FC69DAE20456FC.pdf)。

测试适配使用内部上拉。LSE 已启动时跳过整个 U7 初始化，`g_oled_ui2_u7_result` 返回 `SYS_ERR_NOT_SUPPORTED`，已有调试邮箱仍可使用。发生采样丢边时解码丢弃对角跳变，不把它计作转动；极速转动时可能漏计，方向和实际响应仍需现场对照。

## 实板测试

1. 打开临时工程，选择 `h7_mac_CM4`，仅下载临时 CM4 镜像。启动应看到原四行监控，`g_oled_ui2_u7_result=0`。
2. 短按 U7 后松开，应进入 SYSTEM MENU。每转一档应移动一项，确认双向、首尾停留以及转到第四、第五项时滚动。记录实体顺逆时针对应的菜单方向。
3. 短按进入 Camera，再进入 Status 或 Format。长按约 0.7 秒应只返回一层，松开不会额外触发选择。逐级退回 SYSTEM 后，原游标及滚动窗口应保留；再长按应恢复监控。
4. 快速来回转动、短按和长按各若干次，观察是否跳项、误触发、闪烁或错页。核对 `g_oled_monitor_debug` 的完成帧持续增长，错误计数不增加。需要验证忙期所有权时，按 [验证记录](verification.md) 的帧缓冲检查步骤取证。
5. 如需分离硬件和菜单问题，`g_oled_ui2_debug` 软件邮箱始终可在该临时构建中使用。结束后可恢复正式 CM4 镜像。

## 构建与软件证据

最终正式配置及 U7 临时配置均以 Keil ARMCC 5.06u7 b960 完整构建，零错误、零警告。正式版 Code=26390、RO=1438、RW=936、ZI=3576，与 UI1 基线相同。U7 临时配置 Code=28738、RO=1918、RW=948、ZI=3636。相对正式镜像增加 Flash 2840 B、静态 RAM 72 B；相对纯菜单临时配置增加 Flash 676 B、静态 RAM 32 B。

`python Tests/OledMonitor/run_tests.py --ui2` 在 O0 和 O2 各通过 77 个用例，合计 154 PASS、0 FAIL，61134 条断言。新增用例 76 验证两种相位顺序、抖动抵消、非法跳相、短按、去抖、启动时按住、一次性长按和毫秒回绕。该用例运行同一个纯软件解码器。GPIO、电气、实物方向、实板菜单耗时与刷新所有权均待现场证据，记为 NOT_RUN。
