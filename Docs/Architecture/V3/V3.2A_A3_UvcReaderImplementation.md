Media 是物理 Buffer 权威；A2 CameraTask 是交接记录所有者；UVC Class 是本次源引用和在途包的退休事实来源。USB IRQ 只消费原硬件事件或提交原 Class 的退场事实。UsbTask 是唯一业务 Submit 者，保存 A2 读者状态和该次期望 ID，其他源不参与提交。Class 仅在 PayloadStartView 实际成功后的同一个 IRQ 锁内分配非零 accepted_id，UINT32_MAX 后拒绝回绕。查询不消费或清空记录。新提交保留原 retired_id 与原因；UsbTask 直到 A2 消费确认入队前不会发起下一笔。

归还前必须从公共只读快照确认 accepted_id 和 retired_id 均为预期 ID，且退休原因为 EOF、CANCELLED 或 CLOSED。正常 EOF 用相同 IN completion 序列和包 token 确认末包后清两段引用。取消登记不发布退出；存在在途包时必须 Abort 成功或实际 Close 成功，之后 Payload 的 token 退出操作也必须成功。UVC_ReleaseFrame 现在返回错误，失败保留提交身份、引用和故障状态。DeInit 即使看到 EP1 已关闭仍检查未退休提交和 Payload；只有持有该次 ID 的 Class 才能退休。首错跨同次取消或恢复成功保留。无帧关闭、Class 重建及新的成功 Submit 不覆盖上一退休记录。

## 退出顺序

1. ACTIVE 仅在真实 Commit 和 Alt1 的 can_submit 条件下申请与提交，校验 YUY2、160×120、38,400 B、单段。提交的 BUSY/ERROR 没有接管源才归还；成功后保留原 A2 读者。健康 Suspend 停止正常送包并保留读者，Resume 只有重新实际 CONFIGURED 才恢复。
2. STOP/FAULT 禁止新帧，把原 Cancel、Process、Reader Proof 前置到原 Device STOP 门禁之前。Class 已消失可继续查询旧证明。若两次轮询之间重建出一个空闲 Class，仍要核对旧提交，无法证明时保留 FRAME_HELD、首错和 A2 租约。超时不释放、不自动重启。
3. 匹配证明成立才调用 A2 Release。Camera 实际 ReleaseLease 后回 ACK；UsbTask 消费 ACK 并成功入队 ACK_CONSUMED 方能完成本地数据面退出，Camera 仍按原 A2 规则消费确认后退休。随后才进入既有 USB_Device_Stop 和 Endpoint 检查。Camera 单独 STOP 等待 USB 正常完成或由原控制路径显式 STOP/RECOVER，USB 独立退出不调用 Camera STOP。
4. 保守异常路径仍然可能保持 FAULT，特别是旧 Class 与 Platform 端点账本交错且没有可验证的退休凭据时。现有 Device STOP 从未作为生成旧帧证据的旁路。A1、A2 Dispatcher、Runtime、Platform、BSP 和 ST Core 均未修改。

## 独立 Raw 配置与可复现测试

原 CM7 工程测试宏为 `APP_VIDEO_MJPEG_MODE=0,APP_V3_RAW_UVC_TEST=1`，本轮 Raw 构建移除了本地单 Service 烟测宏。产品正常构建不用 Raw 宏；测试镜像构建后 Keil 两个本地配置恢复到原哈希。A3 不自动 START 两个 Service，板测触发与 Windows 实测在下一门禁执行。
