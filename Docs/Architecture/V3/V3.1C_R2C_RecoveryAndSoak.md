# V3.1C-R2-C 实板启停与恢复

输入基线为用户确认的 [R2-B 实板验收](V3.1C_R2B_BoardAcceptance.md)，提交 `b65f84a`。本轮提供测试脚本和软件验证，R2-C 实板结果仍为 NOT_RUN。

| CM7 编译定义 | 实板场景 |
| --- | --- |
| `APP_V3_BOARD_SMOKE=1/2/3,APP_V3_BOARD_STRESS=1` | Camera / USB / Storage 各 10 次 START、QUERY、STOP、QUERY。最后一轮停止前运行 5 分钟。USB 前 9 轮各保留 30 秒供 Windows 枚举 |
| `APP_V3_BOARD_SMOKE=2,APP_V3_BOARD_STRESS=2` | USB 断连、FAULT、复接、RECOVER、重新枚举、正常停止 |
| `APP_V3_BOARD_SMOKE=3,APP_V3_BOARD_STRESS=2,APP_STORAGE_PARTITION=1` | 使用 R2-B 的 FAT32 第 1 分区测试卡，只读挂载、拔卡、FAULT、插回、RECOVER、再次挂载、容量查询与卸载 |

正式固件默认关闭测试。未设置 STRESS 时仍执行 R2-B 单次测试。三项场景使用原 START、HARDWARE_QUERY、STOP、RECOVER，复用 Control、Queue、Record 和 PubSub。观察窗口内 Control 继续处理消息。超时只终止测试观察，保留原命令结果。

## 首轮 USB 实板操作

本地 CM7 选择 USB RECOVERY。烧录后接好 USB 数据线，复位并让 MCU 连续运行。通过设备管理器观察 Roxy Camera，通过 Keil Watch 的 `g_app_v3_board_smoke` 核对步骤。观察窗口中避免长时间暂停 MCU。

1. `events[0]`、`events[1]` 应为 ACTIVE。在 `OBSERVE / step=2` 的第一个 30 秒窗口内拔掉 USB 数据线，保持板卡供电及调试器连接。
2. 在 `OBSERVE / step=3` 的第二个 30 秒窗口内插回数据线。`events[2]` 应报告 FAULT 和非零首错。
3. `events[3]` 应报告 RECOVER 成功、READY，且保留断连首错。`events[4]`、`events[5]` 应再次为 ACTIVE。Windows 应在后续 30 秒观察窗口内重新识别摄像头。
4. `events[6]`、`events[7]` 应均为 READY、`result=0`，VIDEO_QUIET 位 `0x02` 设置、CONFIGURED 位 `0x01` 清除。最终应为 COMPLETE、`received=8`。保留两次 Windows 识别和最后一次断开的证据。

恢复失败保持 FAULT，脚本不会提交新 START。未拔除而未观察到 FAULT 属于试验条件不满足。Storage 使用相同步骤拔出并插回 SD 卡，不改分区、不写卡。其他卡应先核对其 FAT 分区编号。

## 证据和限制

- `stack_sampled=true` 时，`stack_remaining_words[0..4]` 分别记录 Camera、USB、Control、IPC、Storage 的 FreeRTOS 最小剩余栈。一单位为 4 B。采样在测试终结时执行，包含任务此前的运行史。零余量或未采样时，栈门禁不能关闭。
- `latency_ticks[]` 记录每条命令具备提交条件到匹配终结的 Tick 差，计入队列重试。当前 1 Tick 为 1 ms。这是可观测延时，不能用作 WCET。
- 循环期间的异步故障即使后续 STOP 成功，仍判失败并保留首错。5 分钟保持属于本轮有界检查。
- ARMCC5 夹具对照覆盖 STOP 失败、未观察到断连、RECOVER 失败、断连后 STOP 成功但首错仍在。夹具栈值只核对报告写入。真实栈水位、拔卡、真实恢复失败和更长时间的稳定性仍待实板取证。

本轮未接入 Camera → USB 视频传输。

## 本轮构建与回归结果

ARMCC5 O0/O2 各通过默认 53 项、R2-B 单场景合计 15 项和 R2-C 专项 13 项。完整 USB RECOVERY CM7 Rebuild 为 0 Error、0 Warning，Map 核对 USB 单场景入口和真实 FreeRTOS 栈采样 API。与上次 USB 单项测试相比，USB RECOVERY 的 Flash 净增 300 B、DTCM 净增 224 B。CM4 HEX 哈希和 Keil 用户选项保持原样，其他 R2-C 场景本轮为 ARMCC5 专项编译链接及执行。本地证据位于 `output/ApplicationV3/V3.1C/R2C/`。
