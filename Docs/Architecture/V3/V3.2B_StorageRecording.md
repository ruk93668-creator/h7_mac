# V3.2B Storage 录像与租约归还

## 使用和所有权

`STORAGE_SERVICE_START` 仍只读挂载。已有 Control/Service Mailbox 可提交 `STORAGE_SERVICE_RECORD_START`，非零参数为八位十六进制文件编号。成功结果表示可写挂载已确认并已开放采样。第一张有效 JPEG 才创建 `0:/XXXXXXXX.AVI`，已有同名文件保留。一次请求创建一个有界 AVI，达到配置时间、字节或索引上限时自动停止接收新帧并收尾。`STORAGE_SERVICE_RECORD_QUERY` 返回已完整写入帧数、卷可用扇区、活动/文件/排空标志。普通 `HARDWARE_QUERY` 保留原容量字段。`RECORD_STOP` 和现有 `STOP` 均关闭接收。配置帧率只是采样上限，实板吞吐 NOT_RUN。

Camera 的既有 Dispatcher 以消费者隔离上下行 FIFO、请求号和终结确认。Storage FIFO 复用两个已禁用历史命令通道的物理槽，旧编号仍拒绝发送。JPEG Storage 使用原 FIFO Loan 的 SD 位及会话/编号，保留两段视图。它不调用 Raw Acquire、不伪造 USB Owner、不创建额外物理引用计数。A3 的 USB Raw 配置与此 JPEG 录像配置各自验证，尚无同一配置下 USB+Storage 同时出图录像证据。

StorageTask 同步调用原 AVI/StorageFS。StorageFS 将输入复制到自己的缓冲后再交给 FatFS，SD IDMA 不拿到原帧地址。写入返回即停止读取原 span，之后通过 RETURN、ACK、ACK_CONSUMED 关闭本次交接。消息满或停止超时保留原身份。文件同步/关闭及 FATFS/SD 租约解除仍须独立确认。

历史 V1 `4100e42` 的 `Storage_Finish` 会关闭准入后立即尝试 AVI 关闭及卷卸载，记录槽与 `RETURN_PENDING` 由另一条路径推进。V3 把录像收尾置于本次交接排空之后，保持原文件号和首次写入/收尾故障。失败的 AVI 不生成成功收尾。若原卷已经进入 FAULT，显式 RECOVER 使用 StorageFS 原恢复过程核验文件和介质所有权，再确定是否回到 READY。
