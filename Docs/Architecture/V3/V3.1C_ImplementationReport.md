## C1 异步命令与队列

应用只管理既有 FreeRTOS 静态队列的槽、代次、订阅和销毁门禁。三个 Service 的私有队列和 Record 在 BOOT 准备时建立，普通启停、故障和恢复期间保留原句柄。生产路径当前无完整动态退场操作，队列保留至系统复位。固定 Queue Pool 容量和初始化次序保持 C0 所记录的分配关系。

同一个 Service 同时只推进一项真实命令。公开 API 入队后由所属任务接受；进行中原命令身份保留，FIFO 中后续已接受的消息保持等待。业务推进先于本轮结果 Flush，因此控制队列背压不会阻止必要的停止动作。终结仍使用原 ACK/FAULT、待交付保留和 R1 单一普通任务结果槽。QUERY/RECOVER 在真实 FAULT 后继续可用。BUSY 在有界窗口内跨轮重试，超时仅说明确认未完成。轮次期限不抢占同步的底层 Configure/Mount 等已有函数，实际耗时留待板上测量。

真实命令各服务的编号为 START 16、STOP 17、HARDWARE_QUERY 18、RECOVER 19。原模拟命令编号和标记保留。真实结果用独立 `APP_V3_HARDWARE_RESULT_TAG`，原 52 B 消息的 `frame_id`、`lease_id`、`frame.width`、`frame.height` 和 `frame.size_bytes2` 携带阶段、主值、事实标志、首错和附加值。指针字段保持空，Control 将真实报告解码到 `AppV3ServiceEvent_t.hardware`。模拟运行位保持独立，命令 ID、来源和请求者的运输方式一致。改动只扩展应用内部事件，不改变 AppMessage 布局或 IPC 状态布局。
