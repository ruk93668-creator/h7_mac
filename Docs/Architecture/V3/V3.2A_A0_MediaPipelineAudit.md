## 2. 七槽状态与 DMA 不变量

| 转换 | 唯一提交者 | 前置条件与提交顺序 |
| --- | --- | --- |
| 启动后两槽进入 DMA，其余 FREE | Camera/Media，交由 BSP 启动 | 旧实例已停止且无租约。两槽索引和地址不同，BSP 启动失败沿原回退 |
| FREE 或未借出的 READY → DMA，旧 DMA → READY | BSP 完成回调内由 Media 提交 | DMA TC 与 DCMI FRAME 配对。确认 M0/M1 映射、选中槽不属于 DMA 或消费者、地址区间有效。先写非活动目标并验证硬件，再原子提交映射和已完成帧。替换 READY 时记丢帧 |
| READY → IN_USE | CameraTask 调用 Media | 准入开启、对应消费者无活动租约、全局活动数小于 4。选最新且尚未借出的 READY，事务内记录身份并发布只读 View |
| IN_USE → FREE | CameraTask 调用 Media | 完整租约匹配、跨任务 Return 已消费且提交方已证明没有读取者。未入队的 OFFER 允许由原持有任务取消，因为从未公开 |
| READY → FREE 或 DMA → FREE | Media 原 STOP 清理路径 | 关闭准入。DMA 槽只有实际 STOP 成功后才能清理。存在 IN_USE 时保留槽和身份，等待排空 |
| IN_USE 保持隔离 | Media 和 CameraTask 各保留自己的权威状态 | 替换状态不确定、停止/归还失败、消费者无退出证明。拒绝新的获取，保留首错和凭据 |

[`CameraStream_OwnershipValid`](../../../CM7/Media/Src/camera_capture.c#L977) 核对 M0/M1、READY 指针与单个借出索引，目前要求至少一个 FREE。[`CameraStream_FindReplaceable`](../../../CM7/Media/Src/camera_capture.c#L1018) 在 FREE 超过一个时选 FREE，否则只找最旧 READY。**仅放宽 FREE 校验或仅增加租约槽都不够。** A1 应用同一账本确认两个 DMA 独占、最多四个互不重叠的 IN_USE、其余仅为 FREE 或 READY。活跃时要求至少一个可替换槽，检查 `FREE + 可安全替换 READY >= 1`。候选全部排除 M0/M1 和任何 IN_USE。无候选时按现有故障路径拒绝发布，不进入 HAL。

- **2 DMA + 4 IN_USE + 1 FREE。** 必须允许用唯一 FREE 替换已完成目标，旧 DMA 此时成为 READY，数量仍为 2/4/1。
- **2 DMA + 4 IN_USE + 1 READY。** 必须允许丢弃唯一未借出的 READY，经 BSP 确认后替换。旧 DMA 变为新的 READY。消费者持满时没有新的 Acquire，第五个请求返回 BUSY。
- **任意归还顺序。** 只释放完整凭据匹配的槽。先归还的消费者可在准入未关闭时申请另一个 READY，长期持有者仍独占其槽。READY 的新旧规则建议保持当前“取最新、替换时优先多余 FREE，其次最旧 READY，最后唯一 FREE”。序列回绕只用于选帧排序，身份另行管理。
- **替换失败。** [`Dcmi_StreamTryPair`](../../../CM7/BSP/bsp_dcmi.c#L1291) 检查 TC、FRAME、CT 及晚到 TC，随后调用 [`CameraStream_OnFrameComplete`](../../../CM7/Media/Src/camera_capture.c#L1254) → [`CameraStream_Rotate`](../../../CM7/Media/Src/camera_capture.c#L1051) → [`BSP_DCMI_ReplaceTarget`](../../../CM7/BSP/bsp_dcmi.c#L803)。驱动检查地址区间重叠、EN/DBM、CT、NDTR 余量和 TC 边界，写后 DSB、读回再核对。写后失败可能已改寄存器，驱动保留错误并要求 STOP，没有写回旧地址。此窗口内两侧候选均不准作为新帧发布，既有 IN_USE 不受牵连。不改 BSP 判据。
- **任务与 ISR。** Raw Get/Release 在短 PRIMASK 区间修改表，完成回调在 ISR 发布状态，临界区必须覆盖选择、校验和物理持有提交。复制图像、消息发送、Endpoint 操作和等待放在临界区外。A1 测实际中断屏蔽时长与 DMA 换址余量。

## 3. Dispatcher 与消息接口草案

物理四态归 Media。CameraTask 持有最多四个按消费者索引的静态协议记录，规划 ID 为 USB、Ethernet、Wi-Fi、Storage，本阶段只注册 USB。协议记录绑定物理凭据、原 Request ID、交接阶段及首错，禁止再维护一个物理引用计数。UVC Class 的 `frame_owned` 只代表 Payload 仍引用源帧。Class 归还只允许 UsbTask 提交 Return，由 CameraTask 核对并实际归还。

```c
typedef struct
{
    uint32_t generation;
    uint32_t lease_id;
    uint32_t buffer_id;
    CameraFrameConsumer_t consumer;
} CameraFrameLease_t;

SysResult_t CameraCapture_TryAcquire(CameraFrameConsumer_t consumer,
    CameraFrameLease_t *lease, CameraFrame_t *view);
SysResult_t CameraCapture_ReleaseLease(const CameraFrameLease_t *lease);
```

以上是接口候选。Media 仅接受 CameraTask 正常上下文通过 Dispatcher 调用。Media 从实际槽发布零基 buffer_id。generation 由合法新采集实例分配，lease_id 在实例内单调递增，零保留。generation 与 lease_id 达上限时拒绝复用，禁止回绕；旧 generation、错消费者、错槽、错 lease 均不得改变账本。Acquire 在无 READY、已持有或配额用完时返回 BUSY，在关闭时返回状态错误。Release 对身份错配拒绝，对同一终结的重复请求由 Dispatcher 回送已存结果，不再操作物理槽。候选关闭条件是 Camera 所有者关闭当前代次的新借出并排空有界记录，V3.1C 生命周期仍由原 Service 负责。

沿用 [`AppMessage_t`](../../../CM7/ApplicationV3/Core/app_messages.h#L8) 和四种数据消息 REQUEST/OFFER/RETURN/RETURN_ACK，外加现有 CANCEL_REQUEST 只取消尚未完成的请求。候选字段为 `source→consumer`（仅 Camera 根据经任务校验的 USB 上行来源确认消费者，给 USB 的下行由 Camera 发），`stream_epoch→generation`、`lease_id→lease_id`、`frame_id→buffer_id`（仅帧消息，确认历史 field 使用后再批准）、`command_id→Request ID`。帧的年龄/显示序号不参与归还。仅成功 OFFER 携带 View，负向 OFFER 使用原 Request ID 及权威代次并拒绝旧结果终结新请求。帧数据继续在 SDRAM，只复制描述。上行仅 UsbTask 写、CameraTask 读，下行仅 CameraTask 写、UsbTask 读。须显式验证 source 所有者、方向、类型、代次与请求身份。52 B、IPC 80 B、Control/BOOT 路径均不改。

| 协议节点 | 背压与退休行为 |
| --- | --- |
| 请求已入队 | 等待匹配 OFFER。Cancel 与 Request 同 FIFO。关闭后才被处理的旧 Request 返回关闭结果，不触发 Get |
| 已取得槽，OFFER 未入队 | Camera 保留完整租约和 View，下一轮重试，不再次取得。关闭时只可取消仍由自身独占且从未提交的 OFFER |
| OFFER 已入队或已消费 | Camera 保持租约至 Return，不能以入队失败以外的总线状态撤销已公开帧。UsbTask 在 STOP/关闭后收到旧 OFFER 也必须按原身份 Return |
| RETURN 未入队或 RETURN_ACK 未入队 | 各发送者保存原凭据并重试；Camera Release 成功可立即使物理槽 FREE，协议终结记录仍需保留。重复 Return 只允许重发对应 ACK |
| ACK 已入队 | UsbTask 匹配并消费才可清理当前请求。建议正常运行由同一上行 FIFO 的合法后继 Request 携带上一终结确认，关闭时携带独立带身份的消费确认。A2 必须为既有消息字段和终结确认语义取得批准，或设计等效的显式消费握手。禁用依靠后继才能退场的关闭路径 |

建议每消费者固定一个在途记录及一个终结记录，证据占满就拒绝受理；会话变更要在保证旧回执无法作用于新帧之后。选择具体确认消息或复用字段前，须证明队列满、STOP 期间两边各自背压和迟到 ACK 可以收敛，不要求全局 Camera STOP 才完成 USB 自主退出。

静态池已预留 9 个消息槽及 3 个信号槽，[queue_pool.c](../../../CM7/ApplicationV3/Runtime/queue_pool.c#L7) 和 [service_mailbox.c](../../../CM7/ApplicationV3/Runtime/service_mailbox.c#L10) 对应 6 公共 + 3 Service 命令，另有 Record 信号。重用两条现有 FIFO 不增队列；两条队列当前负载区合计 416 B。[`AppV3EventLoop_Subscribe`](../../../CM7/ApplicationV3/Runtime/service_event_loop.c#L30) 只支持一个可读订阅，`Step` 每轮最多四次命令回调。建议在原 Camera/Usb `Advance` 就地增加小批次/待发推进，使用既有通知和有界轮询兜底，`Advance` 早于 Mailbox Flush（[service_tasks.c:21–47](../../../CM7/ApplicationV3/Tasks/service_tasks.c#L21)）。空闲、FAULT 仍有待发时不可永久睡眠。通知只提示，队列内容才是权威事实；收到队列数据腾出槽后可反向唤醒，仍须覆盖通知丢失。

## 4. UVC 实际读者和停止边界

**正常数据流**：CameraTask 从 Media 取得经过验证的 READY → Camera 将只读 OFFER 入队 → UsbTask 收到后核对同一请求及代次 → `GetStreamStatus.can_submit` 为真才调用 Submit → UsbTask 在有效 Class 内关联当前唯一接受的租约 → `Process` 推进包 → 证明读者退出 → UsbTask Return → CameraTask 核验后 Release → RETURN_ACK 与消费确认。

[`USB_UVC_SubmitFrame`](../../../CM7/Service/usb_uvc_class.c#L256) 包装单段，[`USB_UVC_SubmitFrameView`](../../../CM7/Service/usb_uvc_class.c#L269) 接受分段。JPEG 的 `CameraFrame_t.size_bytes` 是总长，第一段长应为总长减 `size_bytes2`，其次验证两段和边界；该函数在加 USB 锁前读 JPEG 首尾，调用前必须持有租约。Class 锁内核对真实 CONFIGURED、Commit、EP1 open、Alt 1、无 Close pending 和 WAIT_FRAME。BUSY 或失败未接受的租约由 UsbTask 按协议归还，重试时仍只用同一租约并限制等待。[`GetStreamStatus`](../../../CM7/Service/usb_uvc_class.c#L335) 在同一锁内读取 `frame_owned`、`can_submit`、状态与包 token。包 token 不等于 Application 租约。

| 场景 | 权威退出证明与处理 |
| --- | --- |
| 正常 EOF | [`UVC_DataIn`](../../../CM7/Service/usb_uvc_class.c#L1063) 核对 EP、上下文与 IN completion sequence，将匹配包标记 WAIT_CONFIRM。[`USB_UVC_Process`](../../../CM7/Service/usb_uvc_class.c#L366) 核对 token 后推进 Payload；末包完成才结束帧。一条仍在途的提交贯穿快照，在有效 Class 中从该提交观察到 `frame_owned=false` 才允许 Return；计数和通知只作旁证 |
| Payload / Endpoint 读者 | [`USB_UVC_PayloadBuildPacket`](../../../CM7/Service/usb_uvc_payload.c#L107) 从源 span 拷到 Payload 包，Transmit 使用包缓冲。冻结 BSP [`dma_enable=DISABLE`](../../../CM7/BSP/bsp_usb.c#L108)。CPU 读源、EP 仍占包和 App 租约分别记录；当前仍按 Class 不再持帧后 Return，后续切换 USB DMA 模式须重新证明 |
| Cancel / ISO incomplete | [`USB_UVC_CancelFrame`](../../../CM7/Service/usb_uvc_class.c#L315) 的 OK 只表示登记。[`UVC_Incomplete`](../../../CM7/Service/usb_uvc_class.c#L1090) 冻结包错误并进入 RECOVERY。Process 在包 pending 时要求 `USB_Device_AbortEp` 成功，[Platform Abort](../../../CM7/Platform/usb_device.c#L488) 成功才清 busy。BUSY、IO、超时保留租约和首错。确认成功取消才能 Return |
| 健康 Suspend / Resume | 保持原 USB ACTIVE，清 Configured，停止新请求和正常送包，已接受的租约仍有效。Resume 且重新观察到真实 CONFIGURED 后才恢复；主动 STOP 可以沿现有 Cancel/Process 推进，但不得把 Suspend 或静默超时当作归还 |
| Alt 0 / 取消配置 | [`UVC_SetStreamAlt`](../../../CM7/Service/usb_uvc_class.c#L1003) 先封新提交，EP Close 成功后才 `UVC_ReleaseFrame`。[`UVC_DeInit`](../../../CM7/Service/usb_uvc_class.c#L512) Close 失败保留 Class 上下文与持有。成功解绑后旧 Class 查询可能只返回 INVALID_STATE |
| Reset / Disconnect | [`Usb_Reset`](../../../CM7/Platform/usb_device.c#L1387)、[`Usb_Disconnect`](../../../CM7/Platform/usb_device.c#L1456) 经 ST Core DeInit 并继续清理端点。ISR 只把事件通知任务，Reset 事件、Class 不存在、端点 busy=false 都不足以单独确认旧租约。V1 物理拔线检测豁免保持；收到真实 Reset/Disconnect 或显式 STOP 时仍须处理老持有 |
| USB STOP / RECOVER | [`UsbService_StopDevice`](../../../CM7/ApplicationV3/Services/USB/usb_service.c#L167) 先 CheckFrame，再 USB_Device_Stop 与端点检查；[Platform Stop](../../../CM7/Platform/usb_device.c#L1641) 真正停 BSP 后释放 Class 和端点，失败保留 stop_required。A3 需防止“旧 Class 消失→CheckFrame 永久 BUSY→Stop 永无机会产生证明”。先评估现有成功的同实例 Close/Cancel 是否足够；若不够，单独批准最小只读退场事实（Class/传输代次、旧提交关联、确认源引用清除及端点退出），或批准经原 Stop 入口先证实停止后核对源引用的有限调整。不得以 INVALID_STATE 或新 Class 空闲放行旧帧 |

**Camera STOP/FAULT**：原 `CameraService_StopCapture` 的 `frame_held` 只归还本任务的 START 自检帧，禁止让它覆盖 Dispatcher 的消费者租约。CameraTask 关闭准入，继续推进旧 Request/OFFER/Return/ACK。常规 [`CameraCapture_Stop`](../../../CM7/Media/Src/camera_capture.c#L695) 在 CAPTURING 且有借出时返回 BUSY。ERROR 时可走原保护性 STOP，成功后仍可能在 DRAINING 保留 IN_USE。现行 Raw 最后一帧归还直接进 IDLE，四租约须改成最后一个真实借出归还才允许离开 DRAINING，保留现有 JPEG `HasLoan` 语义。[`CameraService_StopMedia`](../../../CM7/ApplicationV3/Services/Camera/camera_service.c#L192) 核对本轮 Stop attempt、硬件结果、是否仍 DRAINING 后才允许传感器 STOP。超时可结束命令为 FAULT 并保留旧身份和首错，任务仍要推进真实归还。USB 单独退场只关闭自己的数据需求，禁止 STOP Camera 或等待其他消费者。全局 Camera STOP 时停止所有新 OFFER，但 USB 已持有帧须通过完成或取消退出，不能等 Camera 先停才 Return。

## 6. 待批准决策与当前风险

1. **首轮格式和七槽适用范围。** 请选择七槽 Raw 的 USB 验收配置，或批准满足七槽目标的 MJPEG 方案。未经确认不得改冻结产品默认格式或将 FIFO 演示作为替代。

3. **旧 Class 消失后的真实退场事实。** A3 前确定可信只读证据或原 STOP 的调用次序最小变更。若现有 API 不能关联旧租约且变更未获批准，这一分支为 BLOCKED。
4. **运行时限与预算。** A1–A4 实测 RAM/栈、DMA 换址临界区、丢帧率与 USB FS 有效带宽。Ethernet、Wi-Fi、Storage 是容量验证中的模拟消费者，当前不接入真实数据面。

本报告是源码和接口设计证据。生产路径、板级七槽共享和 UVC 数据管线仍等待设计审核与后续验证。
