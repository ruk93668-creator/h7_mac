# ApplicationV3.2A A2 — Frame Dispatcher 与跨任务交接

基线 `d9879fce36b8facc50d0fab537374cd2e2be6c8d`，分支 `codex/application-v3-media-usb`。本轮实现 CameraTask 所拥有的 Frame Dispatcher，以及 UsbTask 的请求、读者归还意图和终结确认端点。A1 Raw 账本作为唯一物理所有权来源。三个后续消费者只参加联合专项，产品不主动产生帧请求。冻结配置仍用 MJPEG，A1 Raw API 对 JPEG 返回 NOT_SUPPORTED。真实 UVC 送帧及板级七槽验收留在 A3/A4。

## 权限与 ABI

| 通道 | 生产发送任务及 source | 唯一接收任务 | 允许类型 |
| --- | --- | --- | --- |
| APP_CHANNEL_TO_CAMERA | UsbTask / USB | CameraTask | FRAME_REQUEST、FRAME_CANCEL_REQUEST、FRAME_RETURN、RETURN_ACK_CONSUMED |
| APP_CHANNEL_TO_USB | CameraTask / Camera | UsbTask | FRAME_OFFER、RETURN_ACK |

仍用两个静态深度 4 FIFO，帧消息按值入队，图像仍在原物理槽。方向、类型、调用者和中断上下文全部在运输层检查。未接入历史 Camera/USB 命令通道保持禁用，Control/BOOT 路径保持原有行为。新确认类型追加在既有枚举之后，既有消息编号保持。AppMessage 52 B、frame 偏移 28 B、IPC 状态 80 B、Service 命令 16 B 已测。

匹配键为真实消费者、单调且到上限拒绝的请求号、Media generation、Media lease_id。Camera 独占保存含 buffer_id 的完整 A1 凭据。frame_id 是 Dispatcher 发放顺序，和物理槽号、DMA 目标或裸地址无关。REQUEST / CANCEL 以及负向 OFFER 的 generation、lease_id 为零，只匹配该消费端的原请求号；已发布帧的 RETURN / ACK / ACK_CONSUMED 用非零的真实凭据。重复请求、低于退休高水位的请求、错误身份 Return、提前确认、迟到消息都不改变原物理占用。同一消费者只能有一个事务；会合竞争时首个优先级 USB，成功借出后把下一轮首选者交给下一消费者，空轮次不移动优先级。

## 背压和停止

| 阶段 | Camera 所有者保留的事实 | UsbTask 所有者保留的事实 |
| --- | --- | --- |
| REQUEST | 已受理请求号和准入状态，无帧时保持请求 | 成功入队后等 OFFER。满时返回 NO_RESOURCE，重试用原候选编号 |
| Acquire / OFFER 未入队 | Media 已借且只在 Camera 持有，队列满时保留同一 View 与凭据。取消/关闭可以撤销从未提交的借出 | 取消仅发原请求号；仍接受迟到的匹配 OFFER |
| OFFER 已入队 | 视为消费者可能已读，STOP 不能撤销 | 未交给读者时可直接归还。成功 ReadFrame 后只有明确 ReleaseFrame 才结束读取 |
| RETURN | Camera 只在匹配的 RETURN 后释放，失败保留凭据及首错，后续有界轮次推进 | 上行满时保留归还意图和原身份；本地不再提供 View |
| RETURN_ACK | 实际 Media Release 后物理槽可以复用，ACK 缓存在原记录；入队后该记录保持 WAIT_CONSUMED | 只在实际消费匹配回复后构造 ACK_CONSUMED |
| ACK_CONSUMED | 收到匹配确认后退休终结并保留请求高水位 | 上行满时保存凭据，拒绝额外 Request。确认成功入队后，同一 FIFO 保证确认先于下一笔。最后一笔也必须发送确认 |

负向 OFFER 同样要求消费确认，只取消未发布的租借。通知只用于提早唤醒，Camera/USB 原 Advance 每轮最多接收四条，定期重查保证通知丢失后仍有进展。Camera 在闲置也以现有 10 ms 周期检查数据 FIFO，UsbTask 在活动或存在未完成运输时定期检查。未增加 Runtime 订阅、任务、队列或动态内存。

Camera START 仍要真实取得和归还首帧，自检成功后才开放申请。随后 ACTIVE 只推进 Media 和统计，不再以自检取走业务帧。Camera 接受 STOP 或进入 FAULT 时关闭新借出，继续处理旧请求和回执。原 Media STOP 先验证实际硬件和借用，Camera 在确认关闭前受理的交接全部退休后才完成 STOP；已关闭后拒绝的新请求不抬高停止门禁。失败或超时不会替消费者归还。单路退出仅归还该路租约；USB STOP 等本路交接排空，其他 Camera 使用方继续运行。A2 对实际硬件读者的唯一入口是 UsbTask 明确 ReleaseFrame，A3 仍需证明正常 UVC 完成、取消及旧 Class 消失后的真实读取者退出。
