## 剩余 USB 专项

- Resume。继续使用当前 USB 循环镜像，在一个观察窗口内记录 `s_usb_platform_trace` 的 Suspend 事件和 `dev_state=4 / dev_old_state=3`。保持数据线与供电，尝试由 Windows 打开或选择该摄像头唤醒设备，抓取较新序号的 Resume 以及随后恢复的 `dev_state=3`。是否唤醒取决于实际主机操作，仅凭设备仍显示或没有故障不能验收。该阶段不要求有实时画面。
- 挂起时主动 STOP。独立运行，在 STOP 实际执行前确认 Core 仍为 SUSPENDED、旧状态为 CONFIGURED，然后保留该次 STOP 的 READY、VIDEO_QUIET、配置位清除和最后 QUERY。循环脚本本身使用原有 STOP Request，允许在授权的调试会话中对该次调用短暂取证。
- 拔线恢复。使用 USB RECOVERY 场景。在挂起或运行中断开数据线，独立观察板卡是否收到 Disconnect 或其他可识别故障事实，再复接、RECOVER、重新 CONFIGURED 并 STOP。缺少 Disconnect 时保留 VBUS/板卡证据，不能从 Mock 推断物理拔线能力。

R2-C 整体未关闭。保持现有代码、ABI 和 Service 命令。
