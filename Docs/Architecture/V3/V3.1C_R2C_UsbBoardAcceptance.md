## Suspend 与 Resume 实板证据

同一份 `s_usb_platform_trace` 在 `0x20006D68` 记录事件 #5 Suspend（2343 ms，旧状态 CONFIGURED），随后 #6 Resume（15314 ms）和 #7 Resume（15340 ms），两次 Resume 后的状态均为 CONFIGURED。最终快照 `dev_state=3 / dev_old_state=3 / started=1 / stop_required=0 / last_result=0`。上述事件之间没有 Reset、Disconnect 或重新配置。两张唤醒后截图是同一组事件的重复读取。

用户提供的 FFmpeg DirectShow 日志显示 Windows 打开了 Roxy Camera 并识别 MJPEG 320×240 @ 25 fps。日志无可解码帧，符合本测试镜像未提供视频帧的范围。链路恢复判据来自 Core 事件，实时视频传输仍未验收。

原始截图与 SHA256 保存在本地 `output/ApplicationV3/V3.1C/R2C/UsbSuspendBoardAcceptance/Resume/`。较早的挂起截图单独标注为参考，未与本轮事件拼接。

## 挂起时 STOP 实板证据

按本次调试步骤，用户在 USB_Device_Stop 入口读取 Core 的 `dev_state`、`dev_old_state`，地址为 `0x20009ABC`，值为 `04 03`。继续执行后的报告中，第 3 条 STOP 和第 4 条 QUERY 均为 READY、result=0、first_fault=0、flags=0x0002。截图顶部已进入下一轮观察，未把下一轮状态当作本次 STOP 结果。

原始截图及镜像哈希保存在本地 `output/ApplicationV3/V3.1C/R2C/UsbSuspendBoardAcceptance/StopWhileSuspended/`。

## USB 物理拔线与复接恢复

保持数据线断开的试验在第 3 条 QUERY 后以 `FAILED / step=2 / received=3 / result=-10` 终止，未进入 RECOVER。板端没有观察到脚本要求的 FAULT。另有拔线诊断截图显示健康 Suspend，没有 Disconnect。当前 BSP 关闭硬件 VBUS 检测，原理图与具体控制器事件路径尚待核对。

在第一个窗口内重新接上数据线的补充试验，首错在 10999 ms 冻结。该轮最新事件 #8 是 Reset，设备变为 DEFAULT，Core 原结果为 0，Service 记录 IO 首错。第 3 条 QUERY 记录 FAULT，第 4 条 RECOVER 返回 READY、result=0 并保留 -9；第 5、6 条证明重新 ACTIVE 并配置；第 7 条 STOP 与第 8 条 QUERY 均为 READY、result=0、first_fault=0、flags=0x0002。最终报告为 COMPLETE、received=8、result=0。

补充试验证明复接引发 Reset 后可恢复，板端独立检测物理拔出仍受阻。健康 Suspend 的语义保持不变。原始截图及 SHA256 保存在本地 `output/ApplicationV3/V3.1C/R2C/UsbSuspendBoardAcceptance/DetachRecovery/`。
