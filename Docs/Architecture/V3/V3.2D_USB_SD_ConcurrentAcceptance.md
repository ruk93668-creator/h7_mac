# V3.2D USB / SD 双路视频验收

## 范围和所有权

基线为 `3aa3610a475d5c5ca3157b8cbbb3572971ae1983`，仅交付到 `codex/application-v3-media-usb`。CameraTask 从同一个 512 KiB JPEG FIFO 为 USB 和 Storage 各借一张独立 READY 帧。FIFO 原块引用、7 个 Loan 记录和 DMA 替换规则沿用。USB 最多一个在途租约，按 Session、Loan ID 与原 USB Owner 归还，Legacy 自检入口只能归还自己的 Loan。Storage 仍由原 SD Owner 和同步写入后归还。

UsbTask 将 JPEG 转为一段或两段只读 View，调用原 UVC Class。Submit 成功后保存 Reader ID；只有匹配的 EOF、取消或关闭退休证明才能归还。超过 40,000 B 的 JPEG 整帧跳过并安全归还。两路复用 Dispatcher 的 REQUEST/OFFER/RETURN/ACK/ACK_CONSUMED，并各用原上、下行 FIFO。原 Raw 七缓冲、AVI 写入/收尾、任务和 ST USB Core 保持。

生产改动限于 Camera/USB Service、CameraCapture、JPEG FIFO、UVC 的测试只读协商快照，以及原 ControlTask 和板测头。其余改动为专项及回归夹具。原 Storage 板测和用户 Keil 配置保留。

## 两轮实板流程

两轮均先把对应归档 AXF 和 Map 放到原 CM7 输出目录，选择原 Target 直接 Download，避免 Build。CM4 使用冻结镜像。实板操作由用户执行。所有录像文件使用新编号，只有确认允许写入的测试卡分区才提交录像。

### 第一轮 · JPEG 并行 · 320×240、目标 25 FPS

归档 `Keil-20261123-224920/Recording/`。AXF SHA256 `5AA15AB36E42705D77A55DD30B3DBC6F6AFF0F47C98FDF4AA8584535CB1F51AE`。JPEG 传输为 USB UVC MJPEG，SD 为 JPEG AVI。25 FPS 是协商目标与采样上限，实测另记。

| Watch | 地址 |
| --- | --- |
| g_app_v3_record_command | 0x20008734 |
| g_app_v3_record_board | 0x20008740 |
| g_app_v3_record_storage | 0x20006E3C |
| g_app_v3_record_camera | 0x20006D04 |
| g_app_v3_joint_time_ms | 0x20000098 |
| g_app_v3_joint_camera | 0x20006CD4 |
| g_app_v3_joint_usb | 0x20006F38 |

1. 命令邮箱三个连续 32 位字段为 command、approved_partition、file_number。写入已批准的分区 1 与新文件号，最后写 command=10，Run。确认三路 ACTIVE。Windows 打开 Roxy Camera，核对实际 MJPEG、320×240；设备端记录 Probe、Commit、Alt1 和 Commit 帧间隔 400000（单位 100 ns）。
2. 保持 Windows UVC 打开，在同一段 5–10 秒内保存两组 Watch。每组包括 time_ms、USB completed、SD frames、Camera hardware.primary/detail、FIFO blocks/loans、USB oversize/submit_busy、SD offer 与 frames。实际 FPS 各用本路帧增量除以同一时间差。只有两路同时增长才成立。记录 Windows 实际接收帧数与动态画面，独立于设备端 EOF。
3. command=11 独立停 USB 并保留当前录像，核对 SD 同一文件号仍增帧。用 14 在保留录像的情况下恢复 USB，再确认真正出图。command=9 保留 USB 并停止录像，检查 Reader、USB 帧数、AVI Finish/Close/Unmount 和消费确认。换新文件号用 10 恢复双路，随后用 4 全停，核对 Camera 最后 READY。5、6、13 查询 Camera、Storage、USB；8 采样任务栈，单位为 4 B。
4. 保存底层诊断、两路终结记录和无残留 Loan 快照。只有在 SD READY 且文件已关、FATFS 租约已释放后取卡。将 AVI 复制至 Windows，用 `Tests/ApplicationV3/inspect_recording.py` 核对 movi 与 idx1，完整解码并观察场景变化。全过程不插入拔卡或异常总线复位。

### 第二轮 · Raw YUY2 · 160×120、目标 10 FPS

归档 `Keil-Raw-20261123-225933/`。AXF SHA256 `7C69C6D5B57B0A50D941C10DA6F95A10714289C437B117A781D3C7CE8C6F1711`。沿用 A4.1 本地测试入口；该入口保持为用户现有本地改动。Raw 只验证 USB，现有 MJPEG AVI 写入端要求 JPEG。Full Speed 无法支持 320×240@25 的未压缩 YUY2 带宽。

Watch 为 `g_app_v3_raw_command` 0x20000090、`g_app_v3_raw_measure` 0x20000094、`g_app_v3_raw_board` 0x200085A4、`g_app_v3_raw_camera` 0x20006AD8、`g_app_v3_raw_usb` 0x20006E48。命令 1 启动，Windows 核对实际 YUY2、160×120、10 FPS；measure 写 1/2 标记测量窗口。命令 2 停止，确认 USB 先于 Camera 退出，Reader Proof 与租约归还闭合。
