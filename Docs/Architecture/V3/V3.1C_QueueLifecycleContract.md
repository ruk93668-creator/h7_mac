# V3.1C Queue 生命周期契约

| 对象 | 创建与所有权 | 活动和销毁 |
| --- | --- | --- |
| FreeRTOS 物理 Queue | `Runtime/queue_pool.c` 固定槽、`xQueueCreateStatic` | 内核负责 FIFO、按值复制、有限等待以及 FromISR。应用不暴露内核 Queue 表项。 |
| Queue Pool 句柄 | `AppV3Queue_Alloc` 确定槽和代次；每次访问核验句柄 | 在途 Pin 与订阅门禁均阻止销毁；不允许销毁非空 Queue。ISR 仅使用合法 FromISR 路径，且检查中断优先级。 |
| Service 私有 Queue | Registry 准备后由 Camera/USB/Storage 各自初始化，唯一 Service Task 消费 | 先分配和订阅，随后发布 Record。发布失败才撤回未公开资源。普通 START、STOP、FAULT 和 RECOVER 均沿用原队列。 |
| 公共 Queue | 启动前由 `App_MessagesInit` 分配 | Control 独占启动和业务结果通道。无人消费的四条历史通道继续拒绝发送。 |
| Record 与结果 | Record 由其所属 Service 发布；R1 普通任务结果槽按请求者身份保留 | 既有编号、一个普通任务待领取位置及 ACK/FAULT 背压保持。提交失败撤回结果预留，业务失败不销毁队列。 |

`UNINITIALIZED` 表示尚无 Queue。成功初始化进入 `READY`。硬件开始后进入 `STARTING`，确认业务成立才进入 `ACTIVE`。停止或回退期间为 `QUIESCING`，保留已接受命令并有界推进。确认失败进入 `FAULT`，保留查询和明确的恢复入口。系统目前无动态 Service Task 退场，生产运行不会宣称 `RETIRED`；长期驻留队列保留到复位。

硬件操作占用所属 Service 一个当前命令，按 FIFO 保留后续命令，忙时不从队列取走它们。硬件超时只能导致 FAULT 或待回收，不能证明资源安全。队列临界区仅用于应用元数据与内核传输，真实业务在 Service Task 中执行。配置好的中断只发既有进展通知，继续使用现有优先级和 BSP 事件处理。
