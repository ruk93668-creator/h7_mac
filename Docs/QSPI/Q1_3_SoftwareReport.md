# Q1.3 Page Program 与 Sector Erase 软件交付

审核基线为 `b5c79ecb14956cd04dc2823c34273ca2be70d4da`。本轮软件验证通过，等待 GPT 技术审核。实板编程、擦除、恢复和非均匀阵列四线验收均为 **NOT_RUN**。

## 代码与授权范围

生产差异限 `CM7/BSP/bsp_qspi.c/.h`。新增 `BSP_QSPI_Program(address, buffer, size, timeout_ms, diagnostics)` 和 `BSP_QSPI_EraseSector(address, backup, backup_size, timeout_ms, diagnostics)`。两个公共入口使用同一个 BSP 私有只读常量，授权字节数为 0。没有公共授权接口或开启窗口的编译宏。在没有外设地址映射的 ARM 仿真里，用真实 ST HAL 链接两接口，合法请求均返回 `SYS_ERR_NOT_SUPPORTED`，HAL Tick 调用为 0。虚拟窗口只由 Mock 调用私有函数时传入，未进入 Keil 工程。

原 Read、ReadStatus、初始化和诊断实现保持原样。无动态分配、新任务、Mutex 或 DMA。HAL 句柄、私有操作权、GPIO 和时钟契约保持不变。仅新增加 `06h`、`02h` 和 `20h` 的写事务路径。状态及校验读使用既有 `05h/35h/15h/0Bh`，无状态寄存器写入、解保护、Flash Reset 或其它擦除指令。

Program 在所有范围、状态和目标字节预读检查成功后，才开始按 256 字节页拆分写入。每片独立 WREN、确认 WEL、发送单线 PP 并核验发送长度、轮询 BUSY 及最终状态、逐字节验读。擦除只接受 4 KiB 对齐、完整落在窗口内的扇区，要求传入 4,096 字节原始备份，并在 WREN 前与实际内容逐字节比对。完成后分段检查全部 4,096 字节为 FF。持久化备份和恢复可用性需用外部记录核验。

高风险保护采用整体拒绝策略，BP、CMP 或 WPS 置位均不尝试写入，即使有可能存在未保护地址。BUSY、SUS 和写入前已置位的 WEL 也拒绝。操作共享同一总预算（最多 60,000 ms），轮询窗口分别为 20 ms 和 500 ms，并受剩余总预算约束。器件规格页编程 3 ms、扇区擦除 400 ms；软件裕量待板上方案审核。计时依赖现有持续运行的 HAL Tick。 [Winbond W25Q128JV Rev J §7、§8.2.13、§8.2.15、§9.6](https://www.mouser.com/datasheet/2/949/Winbond_Electronics_Corporation_09_06_2024_W25Q128-3501276.pdf)

单独的写诊断记录操作与线上的最后 opcode、完成长度、失败地址、HAL 结果、CR/DCR/SR、原始状态快照及有效位、耗时和清理结果。编程进度只累计完整验读的页片段，擦除进度累计完整验读的块。若事务可能已发出且完成状态未知，设置 FAULT 和 `flash_completion_unknown`。若已确认 Flash 就绪但验读错误，也锁存 FAULT，并保留已知完成状态。Abort 只做 MCU 清理，任何清理错误独立记录，后续 API 不自动重试或复位。详见 [写入安全契约](Q1_3_WriteSafety.md)。

## 资源与镜像

使用原 Keil 工程的隔离快照，移除隔离副本上的实板诊断宏。工程构建配置哈希与 R2 默认构建一致，本机工程配置未改写。

|内核|Code|RO|RW|ZI|静态栈最大值|
|---|---:|---:|---:|---:|---:|
|CM7|144,334|3,226|1,368|113,384|1,344|
|CM4|26,302|1,438|936|3,576|432|

与 R2 默认镜像相比，CM7 RO 增加 8 字节，为空策略常量，Code/RW/ZI 不变，CM4 资源不变。默认镜像无写 API 调用，链接器剔除了两个写 API 及 HAL Transmit。BSP 复用已有 256 字节暂存区。链接器静态栈统计不包含不可解析的路径，独立门禁测试和软件回归不代表未来获准构建的实板高水位。

AXF 实际负载的半开区间分别是 CM7 `[0x08000000, 0x080241DC)`、CM4 `[0x08100000, 0x08106C88)`。本轮仅构建；没有已授权的实板写入镜像或扇区。

## 后续实板验证材料

1. 待单独批准固定测试扇区、可恢复备份与镜像。读取该 4 KiB 原内容，保存原始字节及哈希到独立介质。人工核对备份后，调用擦除时传入完整备份，BSP 会再次与当前 4 KiB 逐字节比对。试验期间独占该扇区。若备份、权限或恢复方案未满足，所有实板写入保持 NOT_RUN。
2. 在已确认擦除的区域按单页、页末和跨页分别编程，使用 `00 FF 55 AA 0F F0 01 02 04 08 10 20 40 80` 加固定种子伪随机序列。520 字节样本中，前 14 字节为该前缀，其余由 32 位 xorshift(13,17,5) 自 `0x74701301` 迭代取低 8 位。样本的标准 CRC32 为 `0x6AFF4F17`。图案可区分四线位序，尤其 IO1 与 IO2。
3. 分别用 `0x0B`、`0x6B` 读取同址。两路各自与原始图案逐字节比较，记录原始 CRC32、两个读回 CRC32、首个失配的地址/预期值/读回值及实际波形。两路 CRC 相等只作为附加证据。
4. 使用经批准的清理方案，确认 4 KiB 全 FF 后恢复原内容；擦除前的备份核对对象为此时扇区实际内容。原备份留在独立介质用于恢复。恢复后用原备份做整扇区复读比较。任何未知完成状态或失配均停止，保留原备份和首错，等待人工处置。
