## 3. Flash 地址授权流程（尚无地址）

默认禁止任何擦写；本报告不分配测试扇区，也不假定尾扇区空闲。只读识别之后才能申请具体区间。

授权记录必须包含：板卡/PCB 版本、Flash 型号和身份、用途/分区来源、起止 offset（建议半开区间）、容量、4KiB 对齐、允许的命令、次数及有效期、操作者/授权者、批准时间。读取内容为 FF 不是授权。

写入前先只读备份目标及需要保护的相邻区域；未知布局时优先全片只读镜像，保存校验哈希与可恢复副本，并验证读取一致。未知数据的备份不自动赋予破坏许可；若无法确认用途或可靠恢复，不执行擦写。

测试 manifest 与固件授权窗口一致，运行时逐次验证 `size <= end-address`，擦除同时验证完整 sector 包含于窗口；默认空窗、未经明确配置测试构建拒绝写命令。禁止全片擦除和状态寄存器自动改写。测试结束按批准方案恢复并复读比较；电源故障或恢复失败如实记录，不能声称恢复原状。

## 4. 实板测试顺序（全部 NOT_VERIFIED）

1. 取得原理图/PCB，逐网核对六脚、供电、上拉、焊盘；测 VCC 和上电 CS。
2. 隔离测试固件验证时钟、双核启动、TIM6、RTOS，再只读 ID 和 SR1/2/3。保存板号、固件 SHA、探针/工具版本、寄存器及波形。
3. 低速单线读，对同一范围做 Quad 对照；数据需有变化、覆盖各数据线，不能用全 FF 一致就宣称四线正确。必要时待擦写授权后使用测试图案。记录 CLK/NCS/IO0–3 波形。
4. 地址授权后做 sector 擦除、页内与跨页编程及完整读回，窗口外相邻内容前后比较；统计总时延及任务响应。
5. 安全故障注入和恢复：不在未知内容上故意断电，不在擦写中发复位。掉电原子性属于 Q3 专项，Q1 结果不扩张为持久化可靠性证明。
6. 独立集成 target 验证 SDRAM/SDMMC/DCMI/USB 共存；核对 GPIO mux、PLL/RCC 前后值、数据正确性和实时性。Ethernet 基线未接入，共存项保留未验证。

入口设计见 ImplementationPlan §5。任何探针下载也须确认只写内部目标区，不触发外部 Flash 下载算法或全片擦除；烧录动作不在 Q0 范围内。
