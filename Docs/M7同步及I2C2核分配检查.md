# M7 同步及 I2C2 核分配检查

日期：2026-10-16

## 修改点

- CM7/Device/Inc/device.h：同步 DeviceExport_t、DEVICE_EXPORT、BUSY 状态、auto_init 字段和自动注册/初始化接口；保留 CM7 头文件保护宏。
- CM7/Device/Src/device.c：同步自动导出表遍历、BUS 等级注册、DEVICE 等级初始化、生命周期 BUSY 重入保护及注释。
- MDK-ARM/h7_mac.uvprojx：仅在 CM7 Target 增加 --keep=*(.device_export)。既有 M7 Scatter 已包含 ER_DEVICE_EXPORT，本次未改 Scatter。
- OLED 与 bsp_iic 仅由 CM4 Target 启用；未创建 CM7 OLED/IIC 文件。其余共用模块无功能差异，无需覆盖；main 启动、MPU 和 IPC 两核差异保留。

## I2C2 与引脚

- h7_mac.ioc：CortexM4.IPs 包含 I2C2，CortexM7.IPs 不包含 I2C2。
- PB10.PinAttribute=CortexM4，PB10.Signal=I2C2_SCL。
- PB11.PinAttribute=CortexM4，PB11.Signal=I2C2_SDA。
- CM4 BSP：hi2c2.Instance=I2C2；GPIOB PB10|PB11、AF4_I2C2、AF_OD、NOPULL；内核选择 D2PCLK1 并校验 120MHz；Timing=0x307075B1。
- HAL 配置不含 CPU 所有权参数；上述核分配是 CubeMX/工程软件配置，不是硬件访问隔离。M7 不编译执行该 BSP；若未来 M7 直接访问相关寄存器，HAL 不会根据 .ioc 阻止它。

## 验证

- M7 Device 与 Framework 实际源码隔离仿真：14/14 Pass，涵盖状态转换、3×3 回调重入、缺失 Ops、导出表注册、auto_init、Initcall 和失败状态。
- ARMCC5：CM7 全量重编并在增加 keep 后重新链接，0 Error、2 Warning（L6319W、L6314W）。原因均为 M7 尚无 DEVICE_EXPORT 实例，空 .device_export 不匹配；保留将来 M7 设备的注册机制，没有添加占位设备或屏蔽警告。
- CM4 正式 Target 增量编译链接：0 Error、0 Warning。
- CM7 正式 AXF 含 Device_RegisterAll/Device_InitAll 的 Initcall 项，不含 OLED 导出项及 BSP_IIC_Init 注册项。
- 详细仿真结果、两核编译日志位于 Tests/DeviceM7Sync。仿真测试 ELF 使用独立内存布局，不代表上板验证；未验证真实 I2C 波形。
