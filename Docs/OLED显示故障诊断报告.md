# OLED不亮：从软件初始化、总线电平排查到供电方式差异

历史现场：2026-11-02；整理及新观察：2026-11-03。**状态：尚未闭环，不能讲成已经确认硬件短路、假ACK或修复OLED。**

## 面试前先明确当时并不知道什么

最初看到OLED全黑，怀疑没绘制内容、初始化失败、I2C总线异常或模块硬件问题。随后又出现“USB供电不亮，LINK通过DEBUG 5P供电能亮”的新现象，方向才进一步转向供电路径及上电时序。

## 本次推翻或降级的旧结论

旧报告曾把“假ACK”“故障已经定位硬件总线层”“其余功能不受影响”写得过于确定。现有证据不足以支持这些断言，现统一降级为待验证假设。Mock命令序列通过也不能证明真实引脚、供电和I2C通信正确。

旧报告中“已排除CM4未运行”等结论只针对当时进入调试的那次观察，不能外推到USB冷启动的所有场景。旧临时A5/FF自检是否仍在当前固件，应重新看源码，不能把历史记录当作当前状态。

## 已核对的链路

- CM4负责SSD1306 128×32；I2C2，PB10/PB11，7位地址0x3C；固件开漏且不依赖内部上拉。
- CM4先在STOP等待CM7通过HSEM唤醒，再HAL_Init和Framework初始化，随后Application按100ms Timer及Process刷新。
- 不亮可能停在供电、启动、初始化、刷新任意阶段，不以一项READY或错误码0替代完整链路证明。

## 下一步单因素验证，尚未执行完

1. USB独立供电，等电源稳定后按板上RESET；若恢复，优先检查冷启动/复位/面板就绪时序，不能立即宣布加延时即修复。
2. 分别测USB与LINK供电时的VBUS、主板VCC、OLED VCC。万用表看静态，示波器看上升沿、纹波和负载跌落。
3. 保持相同固件和接线，再确认CM4实际位置、init_error及首笔I2C地址/ACK波形，避免不同时间状态互相解释。
4. 检查短路/通断时必须断电；通电只做电压/波形测量，不用通断档。确认LINK电源脚是真正3.3V输出，不能把目标电压参考输入当供电，也不能向VCC接5V。

截至整理，未记录“USB供电后按RESET”的结果，也无两种供电下的完整电压/波形对比。

## 面试60秒复述

> OLED不亮时，我最初按软件问题排查，检查是否真的初始化、有没有显示内容，再关注I2C电平。旧记录中曾出现READY和SCL/SDA低电平并存，这其实是矛盾证据，不能直接断言假ACK或短路。后来我发现USB供电不亮、LINK供电能亮，于是进一步区分是否是调试器启动了CM4；仅供电不进入DEBUG也能亮，让供电路径和上电时序更值得优先检查。核对原理图后发现USB需要经过板上降压，而调试口VCC可直接接入。这项问题还没闭环，所以我会明确说明下一步需要电源波形、复位对照和I2C波形，而不会把推测包装成已修复的硬件故障。
