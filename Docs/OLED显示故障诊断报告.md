## 5. 分析

### 5.1 READY 与"全黑"并存的原因：假 ACK

`HAL_I2C_Master_Transmit` 仅凭 ACK 位是否为低电平判断传输成功。当 SDA 被持续拉低时：

- 地址字节后的 ACK 位被读为 0，判为"从机应答"；
- 数据字节同样全部"成功"；
- 初始化命令序列全部"通过"，`Oled_Init` 返回 `SYS_OK`，设备状态为 `DEVICE_STATE_READY`；
- 但 OLED 实际未收到任何有效命令，显示保持黑屏。

因此 **`DEVICE_STATE_READY` 不能作为"OLED 通信正常"的证据**。

### 5.2 一处需要复测确认的矛盾

若 SCL 在运行期间恒为低电平，主机无法产生时钟，`Oled_Init` 第一笔写就应超时失败（返回 -8）并使 CM4 卡死；而当前观测到的是 `READY`。可能的解释：

- 电平测量时板子未供电：模块上拉随电源失效，总线浮空，万用表读低；
- 短路/虚焊出现在"观测到 READY"之后（返修、补焊、插拔模块）；
- 测量时模块未插入或模块已损坏。

建议复测条件：**板子通电、固件运行、模块插入**状态下测量，并同时用通断档确认 SDA/SCL 与 GND 是否短路。

### 5.3 可能的硬件原因（按可能性排序）

1. **SDA/SCL 对地短路**：焊锡挂锡、座子引脚与相邻地脚搭连、走线与地平面短接；
2. **模块供电异常**：VCC 虚焊/断线导致模块不上电，其板载上拉同时失效，总线被拉低；
3. **上拉电阻缺失或虚焊**：`bsp_iic.c` 使用 `GPIO_NOPULL`，总线电平完全依赖板级或模块板载上拉；
4. **座子/模块引脚错位、SDA/SCL 交叉**：多数表现为 NAK/超时，但需核对；
5. **模块损坏**：ESD 击穿、内部短路。

## 6. 当前结论与影响

- **结论**：故障定位在硬件总线层（SDA/SCL 电平异常），与固件初始化命令序列无关；该序列已在 Mock 仿真验收中验证通过。
- **影响范围**：OLED 无法显示；因假 ACK 使初始化"成功"，CM4 不会卡死，其余 CM4/CM7 功能不受影响；但 OLED 刷新事务会持续返回"成功"，调试信息失真。

## 7. 后续建议（供硬件排查，本次未实施）

1. 断电通断档检查：SDA/SCL 对 GND、对 VCC 是否短路；OLED 座各针脚是否补焊到位；
2. 通电（模块插入）测量：VCC=3.3V，SCL/SDA 空闲≈3.3V；
3. 确认板级/模块上 4.7k 上拉电阻是否在位、是否虚焊；
4. 确认模块型号与针脚定义（4 针 I2C 或 7 针 SPI/I2C 复用），排除 SPI 模式；
5. 硬件修复后，先用无效地址（如 0x50）做 ACK 探针确认真实应答，再进行 0xA5 全亮复测。
